Polyfin is a self-hosted, Jellyfin-compatible server that sources its content from Stremio addons: catalogs, metadata, streams, and subtitles. It provides real user accounts and transcoding, so any Jellyfin client can connect to it like a regular Jellyfin server, without Jellyfin installed.

> [!NOTE]
> Polyfin is in early development: Jellyfin apps can sign in with a password or Quick Connect, browse the libraries, collections, titles, seasons, and episodes the addons provide, with their artwork and search, play the versions their device supports as they are, remuxed into HLS, or transcoded when the app cannot take the video or audio, on an NVIDIA, AMD or Intel GPU when there is one, with the addons' subtitles and the text subtitles inside the files, ASS subtitles with the fonts the files carry, image subtitles burned in when the app cannot show them, and keep each user's watched state, resume points and favorites. HDR video converted to SDR is tone mapped on an NVIDIA GPU up to 1080p, Dolby Vision profile 5 included; elsewhere tone mapping runs on the processor, stops at 720p, and leaves profile 5 out.

## Features

- **Jellyfin-compatible API**: standard Jellyfin clients sign in, browse, search, and play. Polyfin targets the Jellyfin 12.1 API.
- **Stremio addons as the content source**: AIOMetadata for catalogs and metadata, AIOStreams for streams and subtitles, and any other addon that speaks the standard Stremio protocol.
  - Stremio catalogs become Jellyfin libraries. An addon's collection catalogs (such as AIOMetadata's) become collection libraries, where each collection gathers the catalogs it groups, movies and series together.
  - A genre, studio, or year page lists the titles of the catalogs you reach, as libraries or through collections, that offer that name in their genre filter (addons use it for genres, and some for years or studios); titles from catalogs that cannot be filtered by it are not on it.
  - The actors, directors, and writers a title credits open as people, with the photo the metadata addon gives. A person's titles are those your addons' people-search catalogs (such as AIOMetadata's People Search) find for their name, plus the titles of your addons Polyfin already knows them in; without such a catalog, only the latter. The people list holds the people credited in the titles of your addons that someone opened; people credited only in other users' own addons stay hidden.
  - A movie's or series' similar titles come from the first page of the catalogs of your addons that offer one of its genres in their genre filter, ranked by shared genres, directors and actors, and release year, leaving out the title itself and those you played. Trailers reach apps as remote trailers; addons give no other extras.
  - Stremio streams become versions (media sources) of the same item, and addon subtitles become external subtitle tracks. An app's subtitle search lists the user's subtitle addons' subtitles.
  - The subtitles inside a file reach apps that take subtitles only as files, such as jellyfin-web, from the start of playback. ASS subtitles keep their styles and positions, with the fonts the file carries.
  - Stremio TV catalogs (the `tv` type) become Jellyfin Live TV: their channels, numbered in catalog order with their logos, and the programmes of the addons that publish a guide (Stremio's Native EPG).
- **Multiple users**: separate accounts with Jellyfin authentication and Quick Connect. Watched state, favorites, resume points, and Next Up are tracked per user, and each user can be limited to titles up to a rating.
- **Transcoding**: direct play when the client supports the file, with Polyfin redirecting the client to the stream and staying out of the video path; otherwise Polyfin's own on-demand HLS, built on FFmpeg for remote sources: a remux when the app can play the video but not the container, converting the audio when the app cannot take it, and converting the video, HDR to SDR included, when it cannot take that or must have image subtitles (PGS, VobSub, DVB) burned in. Video converts on an NVIDIA GPU through NVENC, or on an AMD or Intel GPU through VAAPI, when one is available, else on the processor.

## How it works

```text
Jellyfin client ──Jellyfin API──> Polyfin ──Stremio protocol──> AIOMetadata / AIOStreams / other addons
      │                              │
      │ direct play: 302 ────────────┼──────────────> debrid / provider URL
      │                              │
      └── transcoding: HLS <── FFmpeg (reads the stream through Polyfin's cache, serves the segments)
```

Polyfin always handles authentication, accounts, browsing, metadata, source selection, and playback state. It reads the remote stream itself only when transcoding, or to relay a source the app could not reach (one that needs request headers or is on a local network address) or a redirect it could not follow, so the direct play or transcoding decision determines how much bandwidth the server uses. Apps never see the addons' stream URLs: they receive Polyfin's own, signed for the user.

## Compatible clients

Polyfin targets the clients that connect to a Jellyfin server, including:

- Swiftfin

- Streamyfin
- Nuvio
- Strand
- Official Jellyfin apps
- Kodi

## Quick start (Docker)

Requirements: Docker with Compose v2. The image, `ghcr.io/moodiness/polyfin`, is published for linux/amd64 and linux/arm64.

```sh
git clone https://github.com/moodiness/polyfin.git
cd polyfin
cp .env.example .env    # then set POSTGRES_PASSWORD, e.g. openssl rand -hex 24
docker compose up -d
```

`POLYFIN_VERSION` in `.env` pins a release, such as `0.1.0`; `latest` follows stable releases. To build the image from source instead, run `docker compose -f compose.yaml -f compose.build.yaml up -d --build`.

Open `http://<server>:8096/admin/`. Polyfin waits for PostgreSQL and creates its tables on startup.

**First run:** until an administrator exists, Polyfin prints a one-time setup code in its log (`docker compose logs polyfin`). Enter it on the setup page to create the administrator, then create the other accounts under **Users**. Jellyfin apps sign in with these accounts, by password or with **Quick Connect**: the app shows a 6-digit code that a signed-in user approves on the Quick Connect page. Users can change their password from Jellyfin apps, which signs their other devices out.

**Language:** the names Polyfin generates for Jellyfin apps (seasons, untitled episodes, and the type that tells apart libraries with the same name, such as "Popular (Movies)") are in English or French, set under **Settings** and defaulting to the language the setup page was in.

**Addons:** paste an addon's manifest URL (from its configure page) under **Addons** to share it with every user, then pick under **Libraries** which of its catalogs become libraries in Jellyfin apps. When an addon offers collection catalogs, those are enabled first; otherwise its first 20 movie, series and TV catalogs are. This is only a starting point: any number of catalogs can be enabled. Each user can also add their own addons and libraries under **My addons**, and turn the server's addons off for themselves. Manifest URLs usually contain your addon settings or keys: Polyfin never shows them in full. Only administrators can install addons hosted on a local network address.

**Catalog limits:** some catalogs are nearly endless, so Polyfin stops reading a catalog after a set number of items. Two settings under **Settings › Catalogs** choose that number. **Titles read per movie and series catalog** applies to every catalog but Live TV ones: 2,000 by default, from 100 to 20,000. **Channels read per Live TV catalog** applies to Live TV catalogs: 10,000 by default, from 100 to 50,000. A higher number shows more, but lists load more slowly and the addons get more requests.

**Artwork:** Polyfin relays images from the addons' artwork servers, so Jellyfin apps only ever talk to Polyfin.

**Playback:** a title's details list every stream the addons offer as a version. The first time a version is played, Polyfin analyzes it with ffprobe (a few seconds) and keeps the result, then tells the app whether it can play it as is, as a Jellyfin server would. The analysis also reads the version's chapters, which apps then show and skip through: those of the version the title was opened or played as, without chapter images; a version never played has no chapters yet. When the app has not picked a version, one that cannot be read is skipped in favor of the next, and the app is told of the other versions too, for apps that let the user pick one at that point. Apps can save the user's playback preferences (audio and subtitle languages, subtitle mode), which choose the default audio and subtitle tracks. Apps that keep titles for offline viewing can download the movies and episodes whose versions they were shown: a download is the version's file, under its file name, sent to the source or relayed as playback would be. Active playback appears in Jellyfin apps' dashboards. Apps can control one another (play, pause, seek, messages) when the controlled app keeps Jellyfin's live connection (WebSocket) open. The skip intro, recap and credits buttons come from [TheIntroDB](https://theintrodb.org) and [IntroDB](https://introdb.app), community databases; Polyfin sends them only titles' IDs, episode numbers and runtimes.

**Playback settings:** under **Settings › Playback**, **Show chapters**, on by default, sends apps the chapters of the versions Polyfin analyzed; they are read along with the analysis every first play needs, so they never delay playback, and turning them off only hides them from apps. **Prepare playback in advance**, off by default, does what the first play of a version waits for as soon as the title's details open in an app: it analyzes the version the title would play, then reads its keyframe index and where its subtitle tracks sit, which HLS playback needs. It readies the next episode the same way, with its versions and subtitles, once the episode playing has 9 minutes left. Playback then starts at once instead of waiting a second or two for these reads. It costs a few more requests to the sources, also for titles opened but not played: at most 2 preparations run at once and 6 start per user each minute, beyond which they are skipped, and a title is prepared once per user every 10 minutes.

**Watching together:** apps that offer SyncPlay, jellyfin-web first, play the same titles in step across devices and users. Anyone in a group can set or change what plays, up to 5,000 entries, play, pause and seek; the group starts and resumes on Polyfin's clock, a little ahead so that every app gets there in time, and waits for the apps still loading or buffering, for 30 seconds at most. Every user may create and join groups, but a group is listed to and joined by only the users who can see everything it plays, and nothing a member cannot see is queued. Like Jellyfin, Polyfin keeps the groups in memory: a session leaves its group when its app disconnects or is signed out (by the app, a password change, or an administrator), and a group ends once empty. The apps need Jellyfin's live connection (WebSocket) open.

**Live TV:** a TV catalog enabled under **Libraries** adds no library: its channels appear in the Live TV view of Jellyfin apps, numbered in the order the catalogs list them. Addons that publish a guide (Stremio's Native EPG: a TV catalog taking a date) fill the programme guide, read a day at a time and kept ten minutes; without one, the guide is empty, as Jellyfin's is without guide data, and the channels play all the same. Polyfin reads at most **Channels read per Live TV catalog** (under **Settings › Catalogs**, 10,000 by default) channels from each TV catalog, and as many programmes from each day of its guide. A channel plays as the addon streams it when the app takes it: an HLS stream is relayed through Polyfin, with the headers the source needs, unless the app can reach the source itself (jellyfin-web always gets it relayed, as browsers cannot read other sites' playlists). Otherwise FFmpeg remuxes it, or converts what the app cannot take, into HLS as it comes, from the moment the app opens the channel until it leaves it (a minute without requests stops it). Polyfin records nothing: there are no recordings or timers.

**Subtitles:** addon subtitles and the text tracks inside a version reach each app in the format it takes. Apps that take subtitles only as files, jellyfin-web first, get the tracks inside a Matroska file read whole through its index, which tells where every subtitle line sits: Polyfin fetches little more than those lines, many in one request when the host allows it, and keeps the track, so it takes seconds the first time and nothing after. ASS tracks keep their styles and positions, and the fonts the file carries are listed for apps that render ASS. A host that answers one byte range at a time would take a request for nearly every line, which providers refuse past a rate: a track that would take it more than 64 requests, the dialogue of a movie for one, is not read so. Those tracks, and the ones the index does not locate, as in MP4 files, are offered as files once a remux has read them whole.

**Watch state:** each user's played titles, resume points, favorites and ratings are kept by Polyfin, so they follow the user from one Jellyfin app to another. Playback moves the resume point and marks a title played near its end, with Jellyfin's thresholds. Continue Watching lists what is under way, and Next Up the next episode of each series being watched. The Upcoming row lists the coming episodes of the series the user watches or marked favorite. Marking a series or a season played marks its released episodes. Apps that keep Jellyfin's live connection (WebSocket) open are told of these changes as they happen, from any of the user's apps. Users can also make playlists of movies and episodes from their apps, private, shared with other users, or open to all.

**Parental control:** under **Users**, an administrator can limit a user to titles up to a rating, and hide from them the movies or shows that have none; administrators' Jellyfin apps can set the same limit from their user settings. A title's rating is the certification the server's metadata addon gives, the US one for AIOMetadata, or the local one when there is no US one; Polyfin also reads the French, German and British ratings and plain ages ("12", "16+"), and a rating it does not know counts as none. Users' own addons never rate titles, and a limited user's apps show the server's addons and libraries only: their own addons are kept but not used, and they cannot turn the server's addons off. Seasons and episodes follow their series. A title above the limit is hidden from the user everywhere, as Jellyfin hides it: libraries, collections, genre, studio and year pages, search, latest, Continue Watching, Next Up, Upcoming, playlists, similar titles and the titles of a person leave it out, people credited only in hidden titles are not listed, and opening, playing, downloading it or searching subtitles for it is refused. Addon catalogs rarely carry ratings, so for a limited user Polyfin asks the metadata addon for each listed title it does not know the rating of yet, a few at a time, once per title: the rating is kept, whichever user opened the title, and asked again after a week, or after a few hours for a title that had none. A listing waits a few seconds for these ratings; it then stops at the titles still unknown, which appear in later listings, and it reads at most a few times as far into a catalog as for a user without a limit. Artwork stays reachable without signing in, as in Jellyfin.

**Conversion and downloads:** two more switches under **Settings › Playback** apply to the whole server. With **Conversion (transcoding)** off, Polyfin never re-encodes video or audio, nor burns subtitles in: apps play files as they are, or remuxed into HLS with their tracks copied, and PlaybackInfo picks the next version that plays so; a title no version of which plays that way on an app does not start on it (Jellyfin's `NoCompatibleStream`), and image subtitles the app cannot show are left out. With **Downloads** off, nobody can download: apps hide their download button and `/Items/{id}/Download` answers 403. Under **Users**, each user also has their own **Can use conversion (transcoding)** and **Can download** permissions, on by default as in Jellyfin; both the server's switch and the user's permission must be on. Administrators' Jellyfin apps set the same permissions through the user policy (`EnableVideoPlaybackTranscoding`, `EnableAudioPlaybackTranscoding`, `EnableContentDownloading`), where video and audio conversion can be allowed separately; the policy shows the user's own permissions, whatever the server's switches.

**Content settings:** under **Settings › Content**, **Skip intro and credits buttons**, on by default, gives apps the intros, recaps and credits to skip; off, `/MediaSegments/{id}` lists none and no segment database is asked, as on a Jellyfin server without a segment provider. **Similar titles**, on by default, lists titles close to the one open; off, every Similar route answers an empty list and no addon catalog is read for it (an unknown title is still not found). **Marked played after (%)** and **Resume point kept after (%)** replace Jellyfin's MaxResumePct and MinResumePct: a position past the first marks the title played, one before the second keeps no resume point. They default to Jellyfin's 90 and 5; unlike Jellyfin, which takes any values, Polyfin keeps the first from 50 to 100 and the second from 0 to 50, and refuses a resume threshold that is not below the played one. A title shorter than 5 minutes is still played as soon as it is past the resume threshold, as in Jellyfin. Under **Settings › Catalogs**, **Keep version lists for (minutes)** (10 by default, from 1 to 360) sets how long a title's versions and subtitles from the addons are kept: longer sends fewer requests to the stream addon, which helps with providers that refuse too many, but new versions show up later. Preparing playback ahead readies the next episode a minute before that life ends, 9 minutes before the end of the episode at most and 1 at least. **Refresh catalogs every (minutes)** (10 by default, from 1 to 1,440) sets how long catalog pages are kept, the Live TV guide's included. Every change applies at once, to what is already kept too.

**Security settings:** **Settings › Security** gathers four settings, which apply at once, without a restart. **Allow users' own addons**, on by default, lets users add addons of their own under **My addons**; under **Users**, each user also has their own **Can add their own addons** permission, on by default. While either is off, the user's own addons are kept but not used: their apps show the server's addons and libraries only, **My addons** says why, their addons cannot be added, replaced, refreshed or turned on (403 `personal_addons_disabled`), and they come back once both are on again. **Block an account after this many wrong passwords**, 0 (never) by default, or 3 to 20: after that many wrong passwords in a row for one account, from a Jellyfin app or the admin interface, the account refuses every sign-in for 15 minutes, the right password included, with the answer of a wrong password. A sign-in, a new password set by an administrator, or **Unblock** under **Users**, where the account shows until when it is blocked, starts the count again, and so does setting the limit to 0. Jellyfin apps read the limit (-1 when there is none) and the count in the user's policy, as `LoginAttemptsBeforeLockout` and `InvalidLoginAttemptCount`; the limit is the server's, so a policy an app posts does not change it, nor the count. Unlike Jellyfin, which disables the account until an administrator enables it again, Polyfin only blocks it for a while, so that the last administrator can never be locked out for good. **Sign out devices unused for**, 0 (never) by default, or 1 to 365 days: Polyfin signs out the Jellyfin apps not used for that many days, at startup and every hour, closing their connections and taking them out of SyncPlay groups as any sign-out does; admin interface sessions are not concerned. **Detailed log**, off by default, has Polyfin log at the `debug` level until it is turned off again, whatever `POLYFIN_LOG_LEVEL` says.

**User playback and access:** under **Users**, each user's **Playback and access** section holds five more limits, which administrators' Jellyfin apps also set from the user's settings. **Playbacks at once** (0, the default, for no limit, up to 20): once that many of the user's other devices are playing, as **Sessions** lists them, PlaybackInfo from one more device answers Jellyfin's `RateLimitExceeded`, which jellyfin-web explains as media that cannot be played at this time; a device already playing can go on to another title. Jellyfin's `MaxActiveSessions` counts signed-in sessions and refuses signing in; Polyfin counts playbacks instead, on purpose, so a user stays signed in on every device, and refuses a policy setting more than 20 (400). **Maximum quality** (no limit by default) caps the bitrate of everything the user plays: PlaybackInfo uses the lower of the app's limit and this one, converts a version above it down to it when the user may use conversion, else plays the next version under it, else nothing (`NoCompatibleStream`). A version above the limit is never played as it is or with its video copied, even from a kept or made-up URL. Jellyfin's `RemoteClientBitrateLimit` applies to remote apps only; Polyfin applies it, on purpose, to all of the user's playback. With **Live TV** off (it is on by default), the Live TV view leaves the user's apps, the `/LiveTv` routes answer 403 as Jellyfin's do without `EnableLiveTvAccess`, and channels and programmes can be neither found nor played. **Watch together** chooses, as Jellyfin's `SyncPlayAccess` does, whether the user may create and join SyncPlay groups (the default), only join them, or not watch together at all, in which case jellyfin-web hides its button: creating a group takes the first, listing and joining groups either of the first two, and other SyncPlay requests answer 403 unless the user is in a group. **Can control other users' apps** (Jellyfin's `EnableRemoteControlOfOtherUsers`) lets the user see and control the apps of other users from theirs; administrators have it when created and when upgrading from an older Polyfin, other users do not, and a user made administrator later keeps the value they had.

**Quality groups:** under **Users**, **Quality group** in **Playback and access**, next to the maximum quality, sets the highest resolution each user is offered: **Original** (the default, no limit), **4K**, **1440p**, **1080p**, **720p** or **480p**. Jellyfin has no such setting: apps neither show nor change it, and a policy they post keeps it. A version's height is the one its analysis found once Polyfin analyzed it, and before that the one its labels name, in the addon's stream name, title, description or file name (2160p, 4K or UHD; 1440p, 2K or QHD; 1080p or FHD; 720p or HD; 576p, 480p or SD); labels that disagree, or name none, leave its height unknown. Versions taller than the group are left out of what the user is offered and of the versions PlaybackInfo tries, and are not analyzed, while one version fits or has an unknown height; the others keep their order. When every version is taller, all are kept rather than none, the closest to the group first (720p before 1080p before 4K, versions of the same height in their order), so that the least is read and decoded, and the one played is converted down to the group, or to **Maximum quality of converted video** when that is lower (and to 1080p at most, as every conversion); a version that fits plays as it is or remuxed as before, while a taller one is never sent at full size, and PlaybackInfo reports its conversion as Jellyfin reports a resolution limit (`VideoResolutionNotSupported`), describing its video at the size sent. A user who may not have video converted (their **Can use conversion** permission, or the server's **Conversion** switch, off) is refused taller versions as other conversions are refused (`NoCompatibleStream`). Live TV channels follow the same rule once analyzed, as their height is only known then, and so do recordings. Only versions that fit can be downloaded, as downloads are never converted: when none fits, the download is refused (403) as without the permission.

**Playback choices:** five more settings at the end of **Settings › Playback** change how PlaybackInfo picks a version and how much video the server converts. Their defaults keep Polyfin as it was, and a change applies to the next request, without a restart. **Maximum time to analyze a version** (45 seconds by default, from 5 to 120) bounds every ffprobe analysis, of files and of live streams: a source that does not answer in time is given up for 15 minutes, and PlaybackInfo moves on to the next version sooner. **Versions tried when one does not work** (3 by default, from 1 to 10) is how many versions PlaybackInfo analyzes when the app picked none, for titles and channels alike; later versions analyzed before are still tried, as they cost nothing. **Prefer versions the app plays without conversion**, off by default, makes PlaybackInfo go on through those versions until one plays on the app as it is or remuxed with its tracks copied, and fall back to the first that plays at all when none does: the first play of a title may analyze more versions, and nothing changes once they are known. A version above the user's **Maximum quality** never counts as one that plays without conversion. Jellyfin 12.1 keeps the version opened first however it plays, as Polyfin does with the setting off. **Video conversions at once** (0 by default, no limit; up to 32) caps the playbacks whose video the server converts, burning subtitles in included, files and Live TV together; Live TV keeps its own caps of 4 channels per user and 16 for the server on top. A playback is what a user plays of a version, from its first converted segment until the app stops it or asks nothing for 3 minutes (1 for Live TV): its next segments, its seeks, and the new play session apps open to switch tracks never count again. At the cap, PlaybackInfo plans no new video conversion, as when conversion is off: it picks the next version that plays without one, else answers `NoCompatibleStream`. An HLS request that would start one more conversion answers 503, as when Live TV is at its cap. Jellyfin has no such cap: its nearest, a tuner's stream limit, fails with a 500, which apps take the same way, as a server error. **Maximum quality of converted video** (Original by default, or 480p to 2160p) scales converted video down to that height, keeping its shape, at the bitrate of that height; a running conversion keeps the size it started with, and files played as they are or with their tracks copied are untouched. Polyfin converts to 1080p at most, so 1440p and 2160p change nothing for now.

**User content:** under **Users**, each user has three more settings, which administrators' Jellyfin apps can also set from their user pages. **Visible libraries** chooses which of the server's libraries the user's apps show: all of them by default, and libraries added later show. It only chooses the libraries shown and blocks no title: a hidden library's titles stay reachable through other libraries, search or links, and listing the library itself is refused as Jellyfin refuses a folder the user may not access (401). Parental control and blocked genres are what block titles. Apps read and set it as the policy's `EnableAllFolders` and `EnabledFolders`; Jellyfin keeps the libraries shown, while Polyfin keeps those hidden, so that a library added later shows even when an app chose the libraries. **Blocked genres** hides the titles of any of these genres, in any letter case, everywhere parental control hides titles: lists, search, details, playback, downloads, Continue Watching, Next Up, similar titles and person pages. A title's genres are those the server's addons give in its complete description, looked up and kept like its rating; a title is hidden until they are known, and a user who blocks genres browses the server's addons only, as under parental control. The admin app offers the genres of the server's libraries, those their genre pages are named after, or any genre typed. Jellyfin has no such setting: its `BlockedTags` are tags, which Polyfin's titles do not have, so the policy reports none and Polyfin ignores those apps send. **Allowed hours** are Jellyfin's access schedules: rows of a day (one day of the week, every day, weekdays or weekends) and a start and end hour from 0 to 24, both included, in the server's time zone. A user with at least one row, outside all of them, cannot sign in (403), and their apps' requests are refused with an empty 403, as Jellyfin does, except reading their own user and the server's information. As in Jellyfin, administrators are refused sign-in outside their hours, but their apps signed in already are served, and a Quick Connect sign-in is not checked, though the app's requests then are. Unlike Jellyfin, which serves direct streams without checking who asks, Polyfin also refuses a user's media outside their hours, and it refuses hours outside 0 to 24 or ending before they start, which jellyfin-web never sends. In the admin app, nobody signs in outside their hours, and a member already signed in sees only who they are.

**Live TV guide (XMLTV):** some IPTV addons publish no Native EPG guide, while their provider publishes one as an XMLTV file. Each TV catalog shown under **Libraries**, or under **My addons** for a user's own, can take the address of such a guide once the libraries are saved. The address may hold the provider's credentials: like manifest URLs, it is never shown in full, and only administrators can use one on a local network address. Polyfin fetches the guide when the address is saved, again every 12 hours, and when **Refresh guide** is pressed; the catalog's row then shows when it was last fetched, how many of its channels the guide covers, and why the last fetch failed, if it did. The file may be plain XML, compressed with gzip, or a ZIP archive (told by its content, not its name), up to 300 MB downloaded and four times as much once uncompressed. Plain and gzip guides are read as they arrive, never whole; a ZIP archive, which can only be read once complete, is first written to a temporary file in Polyfin's cache folder (`POLYFIN_CACHE_DIR`), removed as soon as it is read or fails, and its `.xml` file, the largest if it holds several, is then read the same way; an archive without one is reported as not a guide. The download must answer within 30 seconds, never stall for a minute and end within 10 minutes. A guide channel whose identifier is the channel's Stremio ID takes it. Otherwise its display names are compared with the channel's name once HTML entities left in them are decoded and case, accents, punctuation, separators such as "|", list prefixes such as "FR:", "FR|" or "KIDS|", and marker characters such as ᴴᴰ or ★ are set aside: an exact match keeps quality tags such as HD, FHD, UHD, 4K or SD, a loose one sets them aside too. Many guides list the same channel for several countries, so the candidates are ranked: first those of the channel's own country, the one its prefix names ("FR:"), else the one the server language suggests (France for French; none for English), a guide channel's countries being those of its identifier ("Name.fr") and of its display names' prefixes ("FR|"); then exact matches before loose ones; then the guide channel with the most distinct programme titles in the window kept, so that a placeholder repeating one title ("No Data", or "Name 4K" advertising itself) loses to a real guide; then the first one listed. Each channel takes one guide channel, and several channels, such as a channel and its timeshift copy, may share one; while the guide is read, only the programmes of the best-ranked candidates are kept, and the choice is made at its end. As XMLTV requires, guide channels are expected before their programmes. Only the programmes of the matched channels, from a day before the fetch to eight days after it, are kept, with their title, episode title, description, categories, season and episode numbers and image; a failed fetch keeps those of the last one. They appear wherever Native EPG programmes do (the programme listings, recommended programmes, a programme's details and the programme each channel airs now), with the same filters, and a guide category such as "Movie", "News" or "Sports" marks programmes as a Native EPG genre does. A channel with Native EPG programmes keeps them: the XMLTV guide only fills the channels without. Unlike Jellyfin, whose XMLTV guides belong to its tuner setup, Polyfin attaches a guide to a TV catalog. Programmes from either guide now also give apps their episode title and their season and episode numbers, as Jellyfin's do; `/LiveTv/GuideInfo` still answers the seven days Jellyfin's guide spans.

**Collections:** users who may manage collections group titles into collections from their apps, as Jellyfin's BoxSets (**Add to collection** in jellyfin-web): movies, series, seasons, episodes, an addon's collections and Live TV channels. Collections belong to the server: once one exists, every user's apps show a **Collections** view (CollectionType `boxsets`) listing them by name, a listing of BoxSets across the server lists them too, and a library's Collections tab lists those holding a title from it. Each user sees only the titles they may see: those that parental control or blocked genres hide neither show in a collection nor count in its ChildCount, RecursiveItemCount or played count, and allowed hours apply as everywhere. As in Jellyfin, a collection lists its titles by premiere date and takes their genres, their least restrictive rating and the earliest premiere date; played as a whole, a series brings its released episodes. Its poster is that of the first title the user sees (an episode shows its series' poster), as their listing tags it; without a tag, its first title's. Nothing else is looked up for a collection: Jellyfin's IsLocked is kept as apps send it. Under **Users**, the **Access** section's **Can manage collections** permission (Jellyfin's `EnableCollectionManagement`, which administrators' apps also set from the user's policy) is on for administrators, existing ones included, and off for other users. Without it, `POST /Collections` and `POST` or `DELETE /Collections/{id}/Items` answer an empty 403, as in Jellyfin, administrators included. A collection is deleted as Jellyfin deletes one, with `DELETE /Items/{id}`, which administrators and users who may manage collections may do; others get 401. Unlike Jellyfin: a collection none of whose titles a user may see still shows to them, empty, where Jellyfin hides it; a collection needs a name, and the titles added must be ones the user adding them may see, else the request answers 400 and changes nothing, where Jellyfin creates the collection and then fails (with a 500 for a missing name or an identifier that is not one); collections hold no people, programmes or other users' collections; and the Collections view is not among the visible libraries an administrator chooses, as the Playlists view is not.
**Administration and integrations:** **API keys** (admin app, or jellyfin-web's dashboard through `/Auth/Keys`) let tools such as request managers use the Jellyfin API as Jellyfin's keys do: the key goes as the token of the Authorization header or the `ApiKey` query parameter (`api_key` and `X-Emby-Token` only with legacy authorization), with administrator rights and no user. Requests that name a user (`userId`, `/Users/{id}/…`) act for that user, whose parental control, blocked genres, visible libraries and allowed hours apply; without one they see the server's libraries, and `/Users/Me` answers 400 as in Jellyfin. Polyfin stores only a hash of each key, with its app name, creation date and last use: the admin app shows a key once, and `/Auth/Keys` lists a key made from a Jellyfin app in full only on the next listing, then its identifier, which `DELETE /Auth/Keys/{key}` accepts as well as the key. A key cannot open a WebSocket. Administrators also get Jellyfin's devices (`/Devices`, with custom names; deleting a device signs out every user on it), user creation, renaming and deletion from jellyfin-web (with Polyfin's rules: a password of at least 8 characters is required, unlike Jellyfin, and the last administrator stays), `/Library/MediaFolders`, the server configuration (`/System/Configuration` answers Polyfin's server name, language, resume thresholds, Quick Connect and legacy authorization, with Jellyfin's defaults for the rest; saving applies those fields only and keeps those left out), storage (`/System/Info/Storage`: the cache folder and, when `POLYFIN_RECORDINGS_DIR` is set, the recordings folder), the authentication providers, and the activity log, which records sign-ins and failed ones, playback start and stop, users created, changed or deleted, settings saved and addons installed or removed, keeps 30 days and shows its last entries on the admin app's Status page. `/System/Logs` serves the last 5 MB of the log as one file, `polyfin.log`, kept in memory with URLs reduced to their host and tokens, keys and passwords replaced; apps' uploaded logs (`/ClientLog/Document`, 1 MB at most) go to the log, redacted the same way. `/ScheduledTasks` shows Polyfin's own jobs (signing out unused devices hourly, cleaning the activity log daily, fetching the Live TV guides older than 12 hours, looked for every 30 minutes, or every guide when started by hand, and refreshing ratings, which asks addons and runs only when started) and lets them be started and stopped; their schedules cannot be changed (400). **Forgotten password:** a user on the local network asks for a PIN from the app's sign-in screen; the PIN, valid 30 minutes, is logged and shown on the admin app's **Users** page, as there is no server file to read it from. Entering it in the app makes it the user's password and signs them out everywhere; wrong PINs count as failed sign-ins. Asked from outside the local network, the answer is the same and no PIN is made, as in Jellyfin.
**Live TV recordings:** Polyfin records Live TV programmes, as Jellyfin's DVR does, once `POLYFIN_RECORDINGS_DIR` names a folder it can write to (see Configuration; Polyfin does not start with one it cannot use). Without it, recording is off and Polyfin answers as a server that records nothing: the recording, timer and series timer lists stay empty, what they would hold is not found, and new timers are refused (400). Under **Users**, **Can record Live TV** at the end of **Playback and access** is Jellyfin's `EnableLiveTvManagement`, which apps also read and set in the user's policy: on for administrators, off for other users by default. It lets a user schedule, change and cancel recordings and delete them (403 otherwise, as Jellyfin answers); seeing them needs Live TV only. From a programme of the guide, apps make a timer, which records that programme, or a series timer, which records every programme of the same title in the guide, on the same channel at the same time of day (within ten minutes) unless it records on any channel or at any time, as Jellyfin's do. The guide marks no repeats, so "new episodes only" records every one, and, like Jellyfin, the days of the week a series timer lists are not looked at; **Keep up to** deletes a series' oldest recordings past that many. Guide programmes show their timers (`TimerId`, `SeriesTimerId`). Timers, series timers and recordings are kept in the database. A recording starts **Start recordings early** minutes before its programme and goes on **Keep recording after the end** minutes after it (under **Settings › Recordings**, none by default, as in Jellyfin, from 0 to 60; apps can change them per timer). FFmpeg copies the channel's stream, read as live playback reads it, with the headers it needs and within its addon's confinement, from the guide of the user who scheduled it. It counts among that user's 4 channels played through FFmpeg at once, and the server's 16: past the user's 4, it takes the place of their oldest channel watched, and a channel watched never takes the place of a recording. A stream that stops before the end is read again 30 seconds later. While it records, the file is written in MPEG-TS, which apps can follow at `/LiveTv/LiveRecordings/{id}/stream`; once the programme ends, it becomes one Matroska file in the folder, which plays like a movie's version: as it is, or remuxed into HLS. A recording under way when Polyfin stops is kept as a partial recording when it starts again, and the rest of the programme, if it still airs, is recorded as another. **Keep recordings for** (0, forever, by default, up to 3,650 days) deletes older recordings once a day. Recordings are listed, newest first, under `/LiveTv/Recordings` and in a **Recordings** folder (`/LiveTv/Recordings/Folders`), to the users who reach the channel they come from and to the user who scheduled them; parental control and blocked genres apply to them as to titles (Jellyfin judges recorded videos as "Other" items), and to the programmes users schedule ("LiveTvProgram"). Unlike Jellyfin: a recording plays through PlaybackInfo only once finished; `/LiveTv/LiveRecordings/{id}/stream` needs a signed-in user's credentials or play session, like Polyfin's other media; a timer or series timer asked for a programme Polyfin does not know answers 404 (`Timers/Defaults`) or 400 (`SeriesTimers`) where Jellyfin fails with 500; `POST /LiveTv/Timers/{id}` changes the timer the route names, not the one in the body; Jellyfin's `IsPrePaddingRequired` and `IsPostPaddingRequired` are not kept; and its keep-until choices are kept but only **Keep recordings for** and **Keep up to** delete recordings.

**More for apps:** Jellyfin apps get the rest of what they ask a movie, series and Live TV server for. **Profile pictures**: a user changes their own from their app, an administrator anyone's (`/UserImage`, and the older `/Users/{id}/Images/{type}`); Polyfin keeps a JPEG, PNG or WebP picture of up to 5 MB in the database, scaled down to 512 pixels and stored as JPEG (PNG when it is transparent), shows it in users, sign-in screens and sessions, and on the **Users** page. **Search hints** (`/Search/Hints`) answer from the same search as `/Items`: the movies and series the addons find, then the episodes Polyfin knows by name from series already opened (addons search titles, not episodes), then the people credited in titles the user reaches, all within the user's libraries, parental control and blocked genres; Jellyfin ranks every kind together, Polyfin keeps that order. **Movie recommendations** (`/Movies/Recommendations`) give, for each of the last movies the user played, the "Because you watched" titles similar to it, from the similar titles of title pages and without those already played; Jellyfin's categories for liked titles and for the people of recent movies, which would each cost a search of the addons, are left out, and with **Similar titles** off there are none. `/Years` lists the years the year pages offer (catalogs whose genre filter offers years), `/UserViews/GroupingOptions` the movie and series libraries, `/Items/{id}/Images` a title's artwork, and `/Sessions/Viewing` records the item an app shows, which **Sessions** gives as `NowViewingItem`. Trailer items, plugin channels and theme songs and videos answer empty lists, as on a Jellyfin server without them: addons give trailers only with their titles. Sources need no opening, so `/LiveStreams/Open` answers 400 as Jellyfin does without an open token, and `/LiveStreams/Close` 204. `/Items/{id}/File` serves a title's first working version as the download route does, under the same permissions, which Jellyfin does not ask for its own files. **Fallback fonts** (`/FallbackFont/Fonts`) are the fonts of `POLYFIN_FONTS_DIR`, folders within included, where Jellyfin reads only the top of its folder; the image ships DejaVu (Latin, Greek and Cyrillic), mount more fonts there for other scripts, e.g. CJK. **Subtitle files**: under **Users**, the new **Can manage subtitles** permission (Jellyfin's `EnableSubtitleManagement`, also set from administrators' apps) is on for administrators and off for other users; it lets a user add an SRT, WebVTT, ASS or SSA file to a movie or an episode from their app (`POST /Videos/{id}/Subtitles`), which every version then offers first among its subtitles, and only administrators delete such files (`DELETE /Videos/{id}/Subtitles/{index}`), as in Jellyfin; addon subtitles and tracks inside files cannot be deleted (400). The subtitle search stays open to every user, unlike Jellyfin's, as it lists only what every version already offers; apps show it only with the permission. **Refresh metadata** (`POST /Items/{id}/Refresh`, administrators) makes Polyfin forget the title's description, version and subtitle lists and the rating it looked up, and ask the addons for the description again at once.

**Thumbnails:** **Settings › Thumbnails** makes Jellyfin's scrubbing thumbnails (trickplay) and chapter images, both off by default, because both read parts of the source. They are made after watching, at a gentle pace: once a version has been played, and for the next episode when playback is prepared in advance, Polyfin waits until that playback has stopped and nobody plays anything from the same host, then reads in the background only keyframes, located through the file's index (Matroska Cues or MP4 sample tables), each with a request for its own bytes, never the whole file. A version takes at most 60 requests, its index included, sent one every 3 seconds and at most 120 an hour per host, across versions: past that hour's share, they wait. The keyframes read are spread evenly over the runtime, and every thumbnail, one every **One thumbnail every** seconds (10 by default, from 5 to 60), shows the keyframe read nearest its time, so long movies get coarser thumbnails, a few minutes apart rather than a few seconds; chapter images share the same reads, the keyframe read nearest each chapter's start. Image requests are never retried: a host that asks to slow down (429) or fails as overloaded (502, 503, 504) stops the version at once, nothing of it is kept, the version waits a day, and that host gets no image request for 2 hours, while other hosts go on; a version that fails otherwise is left alone for 30 minutes, or a day when its file cannot give images (no index, an unsupported codec). One version is made at a time, with a short queue. FFmpeg decodes the keyframes, on the GPU when there is one, tone maps HDR, and the thumbnails, **Thumbnail width** wide (240, 320 by default, or 480), are packed into Jellyfin's 10x10 tile JPEGs; chapter images are at most 640 pixels wide. Both are kept in the database: past **Space for images** (2 GB by default, from 1 to 50), the versions whose images were used longest ago lose them, and get them again on their next play. Apps get them as Jellyfin gives them: the item's `Trickplay` field by media source and width, keyed as the item's `MediaSources` name the versions (the first under the title's own identifier) and limited to the versions the user is offered under their quality group, `/Videos/{itemId}/Trickplay/{width}/tiles.m3u8` and `{index}.jpg`, which follow parental control, blocked genres and allowed hours, and chapters' `ImageTag`, served by `/Items/{itemId}/Images/Chapter/{index}` without credentials, like all images. Differences: thumbnails are of the keyframes read, so one may show a moment a few seconds, or on long movies a few minutes, from its time; chapters carry no `ImagePath`; and turning either setting off hides what was made, which shows again when it is turned back on.

**GPU:** at startup Polyfin encodes a few frames on each GPU it can reach, NVIDIA first, then AMD or Intel, and logs the one it converts video on. Give the container an NVIDIA GPU with `--runtime=nvidia` (Compose: `runtime: nvidia`), which needs the NVIDIA Container Toolkit, or Unraid's Nvidia Driver plugin; give it an AMD or Intel GPU with `--device /dev/dri` (Compose: `devices`). On an NVIDIA GPU, HDR is also tone mapped there, through Vulkan, which needs `graphics` among `NVIDIA_DRIVER_CAPABILITIES`, as the image sets them. The container runs as user 65532: when the render nodes in `/dev/dri` are not open to every user, add the group that owns them with `--group-add`.

**Unraid:** the template lives in [`templates/unraid/polyfin.xml`](templates/unraid/polyfin.xml) and needs a PostgreSQL 18 container. To add it, run in Unraid's terminal `wget -O /boot/config/plugins/dockerMan/templates-user/my-Polyfin.xml https://raw.githubusercontent.com/moodiness/polyfin/main/templates/unraid/polyfin.xml`, then choose **Polyfin** under **Docker › Add Container › Template**.

## Configuration

| Variable | Default | Description |
| --- | --- | --- |
| `POLYFIN_DATABASE_URL` | (required) | PostgreSQL URL, e.g. `postgresql://polyfin:password@postgres:5432/polyfin` |
| `POLYFIN_LISTEN` | `:8096` | HTTP address. 8096 is the port Jellyfin clients try by default. |
| `POLYFIN_LOG_LEVEL` | `info` | `debug`, `info`, `warn` or `error`. From `info`, Polyfin logs each Jellyfin endpoint an app calls that it does not serve, with the app's name and version, at most once an hour per endpoint, without the identifiers, query or token of the request. **Settings › Security › Detailed log** switches to `debug` at once, without a restart, and back to this level when turned off. |
| `POLYFIN_FFPROBE` | `ffprobe` | ffprobe executable (FFmpeg 9.0 or later), a path or a name looked up in `PATH`. The Docker image includes one. |
| `POLYFIN_FFMPEG` | `ffmpeg` | FFmpeg executable (9.0 or later), a path or a name looked up in `PATH`. The Docker image includes one. |
| `POLYFIN_CACHE_DIR` | system temporary directory, `/cache` in the Docker image | Where parts of the files being read, and the HLS segments being played, are kept. Emptied when Polyfin starts. |
| `POLYFIN_CACHE_SIZE` | `10GB` | Disk space the parts of files being read may use, e.g. `10GB` or `512MiB`; at least 256 MiB. Parts read in the last 30 seconds are kept even above it. HLS segments come on top: about a minute ahead of each player, up to 1 GB for a 4K remux. |
| `POLYFIN_HWACCEL` | `auto` | GPU video is converted on: `auto` for the first that works, `nvenc` (NVIDIA), `vaapi` (AMD, Intel), or `none` for the processor. |
| `POLYFIN_VAAPI_DEVICE` | each render node in turn | Render node VAAPI opens, e.g. `/dev/dri/renderD128`, when several GPUs could. |
| `POLYFIN_SEGMENTS` | `theintrodb,introdb` | Databases the skip intro, recap and credits buttons come from, the preferred first: `theintrodb`, `introdb`, or `none` for no buttons. They are asked only while **Skip intro and credits buttons** is on under **Settings › Content**; turned off, there are no buttons whatever this says. |
| `POLYFIN_FONTS_DIR` | `/usr/share/fonts`, with DejaVu in the Docker image | Fallback fonts apps load to render subtitles whose own fonts are missing: the `.ttf`, `.otf`, `.woff` and `.woff2` files of this folder and the folders within. Mount more fonts here for other scripts. A missing folder offers none. |
| `POLYFIN_RECORDINGS_DIR` | (unset) | Folder Live TV recordings are written to, an absolute path. Unset leaves recording off. Polyfin must be able to write to it, or it does not start. |

The Compose files read their own settings (passwords, ports, image version) from `.env`; see [`.env.example`](.env.example).

## Development

Requirements: Go 1.27, Node.js 24, a PostgreSQL 18 server, and FFmpeg 9.0 or later (`ffmpeg` and `ffprobe`) to play titles. With `POSTGRES_PASSWORD` set in `.env`, `docker compose up -d postgres` starts one on `127.0.0.1:5432`.

```sh
export POLYFIN_DATABASE_URL=postgresql://polyfin:password@127.0.0.1:5432/polyfin
make dev                      # builds the admin app, then runs the server on :8096
npm --prefix web run dev      # optional: admin app with hot reload, proxied to :8096
make check                    # formatting, vet and tests
```

Database tests run when `POLYFIN_TEST_DATABASE_URL` points to a disposable PostgreSQL database, and remux tests when `POLYFIN_TEST_FFMPEG` names an `ffmpeg` executable with `ffprobe` beside it; CI always provides both. Each database test works in its own schema.

Jellyfin API responses are checked against the JSON structure of a real Jellyfin 12.1 server, recorded in `internal/jellyfin/testdata/`. `scripts/jellyfin-fixtures.sh` records them again from a disposable Jellyfin container (requires Docker, curl and jq).
