Polyfin is a self-hosted, Jellyfin-compatible server that sources its content from Stremio addons (catalogs, metadata, streams, and subtitles), Eclipse music addons (music, audiobooks, and podcasts), and IPTV sources (M3U playlists and Xtream Codes accounts, with XMLTV guides). It provides real user accounts and transcoding, so any Jellyfin client can connect to it like a regular Jellyfin server, without Jellyfin installed.

> [!NOTE]
> Polyfin is in early development: Jellyfin apps can sign in with a password or Quick Connect, browse the libraries, collections, titles, seasons, and episodes the addons provide, with their artwork and search, play the versions their device supports as they are, remuxed into HLS, or transcoded when the app cannot take the video or audio, on an NVIDIA, AMD or Intel GPU when there is one, with the addons' subtitles and the text subtitles inside the files, ASS subtitles with the fonts the files carry, image subtitles burned in when the app cannot show them, and keep each user's watched state, resume points and favorites. HDR video converted to SDR is tone mapped on an NVIDIA GPU up to 1080p, Dolby Vision profile 5 included; elsewhere tone mapping runs on the processor, stops at 720p, and leaves profile 5 out.

## Features

- **Jellyfin-compatible API**: standard Jellyfin clients sign in, browse, search, and play. Polyfin targets the Jellyfin 12.1 API.
- **Stremio addons as the content source**: AIOMetadata for catalogs and metadata, AIOStreams for streams and subtitles, and any other addon that speaks the standard Stremio protocol.
  - Stremio catalogs become Jellyfin libraries. An addon's collection catalogs (such as AIOMetadata's) become collection libraries, where each collection gathers the catalogs it groups, movies and series together.
  - A genre, studio, or year page lists the titles of the catalogs you reach, as libraries or through collections, that offer that name in their genre filter (addons use it for genres, and some for years or studios); titles from catalogs that cannot be filtered by it are not on it.
  - The actors, directors, and writers a title credits open as people, with the photo the metadata addon gives. A person's titles are those your addons' people-search catalogs (such as AIOMetadata's People Search) find for their name, plus the titles of your addons Polyfin already knows them in; without such a catalog, only the latter. The people list holds the people credited in the titles of your addons that someone opened; people credited only in other users' own addons stay hidden.
  - A movie's or series' similar titles come from the first page of the catalogs of your addons that offer one of its genres in their genre filter, ranked by shared genres, directors and actors, and release year, leaving out the title itself and those you played. Trailers reach apps as remote trailers; addons give no other extras.
  - Stremio streams become versions (media sources) of the same item, and addon subtitles become external subtitle tracks. An app's subtitle search lists the user's subtitle addons' subtitles.
  - The subtitles inside a file reach apps that take subtitles only as files, such as jellyfin-web, from the start of playback. ASS subtitles keep their styles and positions, with the fonts the file carries.
  - Stremio TV catalogs (the `tv` type) become Jellyfin Live TV: their channels, numbered in catalog order with their logos, and the programmes of the addons that publish a guide (Stremio's Native EPG).
- **Multiple users**: separate accounts with Jellyfin authentication and Quick Connect. Watched state, favorites, resume points, and Next Up are tracked per user, and each user can be limited to titles up to a rating.
- **Tracking services**: each user can connect their own Trakt, Simkl, MDBList and PublicMetaDB accounts, which then hear of the movies and episodes they watch and mark played.
- **Transcoding**: direct play when the client supports the file, with Polyfin redirecting the client to the stream and staying out of the video path; otherwise Polyfin's own on-demand HLS, built on FFmpeg for remote sources: a remux when the app can play the video but not the container, converting the audio when the app cannot take it, and converting the video, HDR to SDR included, when it cannot take that or must have image subtitles (PGS, VobSub, DVB) burned in. Video converts on an NVIDIA GPU through NVENC, or on an AMD or Intel GPU through VAAPI, when one is available, else on the processor.

## How it works

```text
Jellyfin client ──Jellyfin API──> Polyfin ──Stremio protocol──> AIOMetadata / AIOStreams / other addons
      │                              │
      │ direct play: 302 ────────────┼──────────────> debrid / provider URL
      │                              │
      └── transcoding: HLS <── FFmpeg (reads the stream through Polyfin's cache, serves the segments)
```

Polyfin always handles authentication, accounts, browsing, metadata, source selection, and playback state. It reads the remote stream itself only when transcoding, or to relay a source the app could not reach (one that needs request headers or is on a local network address) or a redirect it could not follow, so the direct play or transcoding decision determines how much bandwidth the server uses. Apps never see the addons' stream URLs: they receive Polyfin's own, signed for the user.

## Compatible clients

Polyfin targets the clients that connect to a Jellyfin server, including:

- Swiftfin
- Findroid
- Streamyfin
- Nuvio
- Strand
- Official Jellyfin apps
- Kodi

## Quick start (Docker)

Requirements: Docker with Compose v2. The image, `ghcr.io/moodiness/polyfin`, is published for linux/amd64 and linux/arm64.

```sh
git clone https://github.com/moodiness/polyfin.git
cd polyfin
cp .env.example .env    # then set POSTGRES_PASSWORD, e.g. openssl rand -hex 24
docker compose up -d
```

`POLYFIN_VERSION` in `.env` pins a release, such as `0.1.0`; `latest` follows stable releases. To build the image from source instead, run `docker compose -f compose.yaml -f compose.build.yaml up -d --build`.

Open `http://<server>:8096/admin/`. Polyfin waits for PostgreSQL and creates its tables on startup.

**First run:** until an administrator exists, Polyfin prints a one-time setup code in its log (`docker compose logs polyfin`). Enter it on the setup page to create the administrator, then create the other accounts under **Users**. Jellyfin apps sign in with these accounts, by password or with **Quick Connect**: the app shows a 6-digit code that a signed-in user approves on the Quick Connect page. Users can change their password from Jellyfin apps, which signs their other devices out.

**Language:** the names Polyfin generates for Jellyfin apps (seasons, untitled episodes, and the type that tells apart libraries with the same name, such as "Popular (Movies)") are in English or French, set under **Settings** and defaulting to the language the setup page was in.

**Addons:** paste an addon's manifest URL (from its configure page) under **Addons** to share it with every user, then pick under **Libraries** which of its catalogs become libraries in Jellyfin apps. When an addon offers collection catalogs, those are enabled first; otherwise its first 20 movie, series and TV catalogs are. This is only a starting point: any number of catalogs can be enabled. Each user can also add their own addons and libraries under **My addons**, and turn the server's addons off for themselves. Manifest URLs usually contain your addon settings or keys: Polyfin never shows them in full. Only administrators can install addons hosted on a local network address.

**Music addons:** Eclipse music addons install like Stremio addons, under **Addons** for the server or **My addons** for a user's own, by their manifest URL or their base address (`https://addon.example/{token}/`); Polyfin tells them apart by their manifest, and their addresses are redacted like manifest URLs. The settings an addon declares (pickers, switches, texts and numbers) are changed from its **Settings** button under **Addons** or **My addons**, one value each, a per-network setting keeping its Wi-Fi default, and travel as query parameters with every request to the addon, as Eclipse sends them. Each catalog row (songs, albums, artists or playlists) is a library under **Libraries**, a Jellyfin music library (CollectionType `music`), or a books library for an addon whose `contentType` is `audiobook`, whose tracks are AudioBook items with the chapters their stream gives. Podcasts have no Jellyfin type: their episodes are songs (Audio). A row lists its own items; asked for another kind, a library derives it: the albums and artists its songs name, or the songs of its albums, playlists or artists, reading at most 50 of their pages. An album or artist a song only names is found again through the addon's search when opened, so addons without catalogs still serve search and album, artist and playlist pages. Jellyfin music apps browse `/Artists`, `/Artists/AlbumArtists`, `/Items` by `parentId`, `artistIds` or `albumIds` with Jellyfin's sorting and paging, the latest albums, search and search hints through the addons' `/search`, and the addons' artwork. Instant mixes differ from Jellyfin's, which pick songs sharing genres that addons rarely give: a song's mix is that song, then its album's and its artist's other songs; an album's, its songs and its artist's; an artist's or a playlist's, their songs; shuffled. Addons give no lyrics: the lyrics endpoints answer as Jellyfin does for a song without any. Playback decides with the app's device profile as Jellyfin decides for audio, from the codec, container, sample rate and bit depth the addon's stream reply gives (the stream is analyzed only when it gives none; a lossless stream's bitrate, which the reply does not give, is taken as that of its samples in stereo, so that a bitrate limit converts it), plays the track as it is through the same source and relay rules as videos, or converts it with FFmpeg to the codec, bitrate, sample rate and channels the app asks, progressively or in 3-second HLS segments; an expired link is asked for again, before it expires (`expiresAt`) or once it fails. The user's conversion permission, bitrate limit and playbacks at once apply; quality groups, about video heights, do not. Playback reports count plays and mark songs played, without resume points as in Jellyfin, while audiobooks keep theirs with Jellyfin's audiobook thresholds, and the activity log records audio playback as Jellyfin does. Their requests count in **Health** like a Stremio addon's: last answer, failures and response time, with the same manifest check. Explicit songs and albums are hidden from users whose parental control sets a highest rating, and all music (books for audiobooks) from users who block unrated music, since music has no rating; visible libraries and allowed hours apply as elsewhere. Eclipse's video renditions are not used: Jellyfin music apps cannot show a video for a song.

**Catalog limits:** some catalogs are nearly endless, so Polyfin stops reading a catalog after a set number of items. Two settings under **Settings › Catalogs** choose that number. **Titles read per movie and series catalog** applies to every catalog but Live TV ones: 2,000 by default, from 100 to 20,000. **Channels read per Live TV catalog** applies to Live TV catalogs: 10,000 by default, from 100 to 50,000. A higher number shows more, but lists load more slowly and the addons get more requests.

**Artwork:** Polyfin relays images from the addons' artwork servers, so Jellyfin apps only ever talk to Polyfin. Seasons show their own poster when the metadata addon lists the seasons' posters, as Jellyfin shows a season's own image; a season without one shows its series' poster. Such a list names no season: Polyfin reads it only when it has one poster per season of the series' episodes, specials included or left out, and otherwise shows the series' poster on every season rather than risk showing a season another's. It asks the addon for nothing more: the posters come with the series' description.

**Playback:** a title's details list every stream the addons offer as a version. The first time a version is played, Polyfin analyzes it with ffprobe (a few seconds) and keeps the result, then tells the app whether it can play it as is, as a Jellyfin server would. The analysis also reads the version's chapters, which apps then show and skip through: those of the version the title was opened or played as, without chapter images; a version never played has no chapters yet. Versions always keep the addons' order: picking or playing one never moves it. Jellyfin 12.1 lists first the version an app opens as an item, which jellyfin-web's version menu does once a version is picked, so the menu reorders itself there; Polyfin keeps it as it was. When the app has not picked a version, one that cannot be read, or does not play on the app, is skipped in favor of the next, and left out of the versions PlaybackInfo lists, which keep their order from the one chosen, for apps that let the user pick one at that point; Jellyfin lists them all. Apps can save the user's playback preferences (audio and subtitle languages, subtitle mode), which choose the default audio and subtitle tracks. Apps that keep titles for offline viewing can download the movies and episodes whose versions they were shown: a download is the version's file, under its file name, sent to the source or relayed as playback would be. Active playback appears in Jellyfin apps' dashboards. Apps can control one another (play, pause, seek, messages) when the controlled app keeps Jellyfin's live connection (WebSocket) open. The skip intro, recap and credits buttons come from [TheIntroDB](https://theintrodb.org) and [IntroDB](https://introdb.app), community databases; Polyfin sends them only titles' IDs, episode numbers and runtimes.

**Playback settings:** under **Settings › Playback**, **Show chapters**, on by default, sends apps the chapters of the versions Polyfin analyzed; they are read along with the analysis every first play needs, so they never delay playback, and turning them off only hides them from apps. **Prepare playback in advance**, off by default, does what the first play of a version waits for as soon as the title's details open in an app: it analyzes the version the title would play, then reads its keyframe index and where its subtitle tracks sit, which HLS playback needs. It readies the next episode the same way, with its versions and subtitles, once the episode playing has 9 minutes left. Playback then starts at once instead of waiting a second or two for these reads. It costs a few more requests to the sources, also for titles opened but not played: at most 2 preparations run at once and 6 start per user each minute, beyond which they are skipped, and a title is prepared once per user every 10 minutes.

**Watching together:** apps that offer SyncPlay, jellyfin-web first, play the same titles in step across devices and users. Anyone in a group can set or change what plays, up to 5,000 entries, play, pause and seek; the group starts and resumes on Polyfin's clock, a little ahead so that every app gets there in time, and waits for the apps still loading or buffering, for 30 seconds at most. Every user may create and join groups, but a group is listed to and joined by only the users who can see everything it plays, and nothing a member cannot see is queued. Like Jellyfin, Polyfin keeps the groups in memory: a session leaves its group when its app disconnects or is signed out (by the app, a password change, or an administrator), and a group ends once empty. The apps need Jellyfin's live connection (WebSocket) open.

**Live TV:** a TV catalog enabled under **Libraries** adds no library: its channels appear in the Live TV view of Jellyfin apps, numbered in the order the catalogs list them. Addons that publish a guide (Stremio's Native EPG: a TV catalog taking a date) fill the programme guide, read a day at a time and kept ten minutes; without one, the guide is empty, as Jellyfin's is without guide data, and the channels play all the same. Polyfin reads at most **Channels read per Live TV catalog** (under **Settings › Catalogs**, 10,000 by default) channels from each TV catalog, and as many programmes from each day of its guide. A channel plays as the addon streams it when the app takes it: an HLS stream is relayed through Polyfin, with the headers the source needs, unless the app can reach the source itself (jellyfin-web always gets it relayed, as browsers cannot read other sites' playlists). Otherwise FFmpeg remuxes it, or converts what the app cannot take, into HLS as it comes, from the moment the app opens the channel until it leaves it (a minute without requests stops it). Polyfin records nothing: there are no recordings or timers.

**Subtitles:** addon subtitles and the text tracks inside a version reach each app in the format it takes. Apps that take subtitles only as files, jellyfin-web first, get the tracks inside a Matroska file read whole through its index, which tells where every subtitle line sits: Polyfin fetches little more than those lines, many in one request when the host allows it, and keeps the track, so it takes seconds the first time and nothing after. ASS tracks keep their styles and positions, and the fonts the file carries are listed for apps that render ASS. A host that answers one byte range at a time would take a request for nearly every line, which providers refuse past a rate: a track that would take it more than 64 requests, the dialogue of a movie for one, is not read so, nor offered as a file: Polyfin learns whether the host serves several ranges at once before it offers such a track, from what it already knows of the host or with one request for two ranges, and logs the tracks it leaves out. Those tracks, and the ones the index does not locate, as in MP4 files, are offered as files once a remux has read them whole.

**Watch state:** each user's played titles, resume points, favorites and ratings are kept by Polyfin, so they follow the user from one Jellyfin app to another. Playback moves the resume point and marks a title played near its end, with Jellyfin's thresholds. Continue Watching lists what is under way, and Next Up the next episode of each series being watched. The Upcoming row lists the coming episodes of the series the user watches or marked favorite. Marking a series or a season played marks its released episodes. Apps that keep Jellyfin's live connection (WebSocket) open are told of these changes as they happen, from any of the user's apps. Users can also make playlists of movies and episodes from their apps, private, shared with other users, or open to all.

**Tracking services:** each user can send what they watch to their own accounts on Trakt, Simkl, MDBList and PublicMetaDB, connected under **My account › Tracking** in the admin app. Trakt and Simkl show a code to enter on their site; MDBList and PublicMetaDB take the user's API key (MDBList's from its preferences, PublicMetaDB's from **Settings › API** on its site), which Polyfin checks with the service before saving it. Only movies and episodes known by an IMDb, TMDB or TVDB identifier are sent, episodes by their series' identifiers and their season and episode numbers: Live TV, recordings, music and titles without an identifier send nothing, and one user's activity never reaches another user's accounts.

- **Playback:** starting, pausing, resuming and stopping a title reach Trakt, Simkl and MDBList as they happen (scrobbling), with how far into the title playback is; each service decides from it whether the title was watched, as for its other apps (from 80%). PublicMetaDB, which does not follow playback, gets a resume point when playback pauses or stops, and the title in its history once Polyfin marks it played (**Marked played after (%)** under **Settings › Content**).
- **Played marks:** marking a movie, an episode, a season or a series played or unplayed from an app adds its movies and episodes to the history of each service, or removes them; so does an app that uploads a movie or an episode as played or unplayed through its user data, as apps do with what they played offline. A mark sends only what Polyfin counts as a new play: marking played again what already is, without a date, sends nothing. One viewing makes one history entry: a played mark within six hours of a service counting the same title watched from its playback is not sent to that service again.
- **Delivery:** nothing waits for the services: reports and marks are sent in the background, at the pace each service allows (one change a second per user for Trakt and Simkl, PublicMetaDB's limit per server address), waiting as long as a service asks when it answers too many requests. Changes to the history and resume points are kept in the database and sent again, with longer waits each time, for up to two days, restarts included; starts and pauses are sent once. A service that refuses the user's token or key shows **Connect again** and gets nothing more until the user connects it again; one that keeps failing shows as unreachable while Polyfin retries. Trakt and Simkl tokens are refreshed before they expire and revoked when the user disconnects. Deleting a user deletes their connections and what waited to be sent. Tokens and keys are never shown, nor written to the log.
- **Setup:** MDBList and PublicMetaDB need nothing from the administrator. Trakt and Simkl are offered once an administrator registered an app with them and pasted its credentials under **Settings › Tracking**. For Trakt, create an application in your [Trakt API apps](https://app.trakt.tv/settings/apps) with the redirect URI `urn:ietf:wg:oauth:2.0:oob`, then paste its **Client ID** and **Client Secret** in **Trakt client ID** and **Trakt client secret**. For Simkl, register an app in your [Simkl developer settings](https://simkl.com/settings/developer/), of the **TV, devices & command line** type (Simkl's AUTH V2, which needs no redirect URI; client IDs of older AUTH V1 apps are refused), then paste its client ID in **Simkl client ID**. The secret is never shown again once saved. When Trakt or Simkl refuses the server's app, a wrong client ID or secret, users connecting are told that an administrator has to check it under **Settings › Tracking**, rather than that the service is down.

**Parental control:** under **Users**, an administrator can limit a user to titles up to a rating, and hide from them the movies or shows that have none; administrators' Jellyfin apps can set the same limit from their user settings. A title's rating is the certification the server's metadata addon gives, the US one for AIOMetadata, or the local one when there is no US one; Polyfin also reads the French, German and British ratings and plain ages ("12", "16+"), and a rating it does not know counts as none. Users' own addons never rate titles, and a limited user's apps show the server's addons and libraries only: their own addons are kept but not used, and they cannot turn the server's addons off. Seasons and episodes follow their series. A title above the limit is hidden from the user everywhere, as Jellyfin hides it: libraries, collections, genre, studio and year pages, search, latest, Continue Watching, Next Up, Upcoming, playlists, similar titles and the titles of a person leave it out, people credited only in hidden titles are not listed, and opening, playing, downloading it or searching subtitles for it is refused. Addon catalogs rarely carry ratings, so for a limited user Polyfin asks the metadata addon for each listed title it does not know the rating of yet, a few at a time, once per title: the rating is kept, whichever user opened the title, and asked again after a week, or after a few hours for a title that had none. A listing waits a few seconds for these ratings; it then stops at the titles still unknown, which appear in later listings, and it reads at most a few times as far into a catalog as for a user without a limit. Artwork stays reachable without signing in, as in Jellyfin.

**Conversion and downloads:** two more switches apply to the whole server: **Conversion (transcoding)** under **Settings › Conversion** and **Downloads** under **Settings › Playback**. With **Conversion (transcoding)** off, Polyfin never re-encodes video or audio, nor burns subtitles in: apps play files as they are, or remuxed into HLS with their tracks copied, and PlaybackInfo picks the next version that plays so; a title no version of which plays that way on an app does not start on it (Jellyfin's `NoCompatibleStream`), and image subtitles the app cannot show are left out. With **Downloads** off, nobody can download: apps hide their download button and `/Items/{id}/Download` answers 403. Under **Users**, each user also has their own **Can use conversion (transcoding)** and **Can download** permissions, on by default as in Jellyfin; both the server's switch and the user's permission must be on. Administrators' Jellyfin apps set the same permissions through the user policy (`EnableVideoPlaybackTranscoding`, `EnableAudioPlaybackTranscoding`, `EnableContentDownloading`), where video and audio conversion can be allowed separately; the policy shows the user's own permissions, whatever the server's switches.

**Content settings:** under **Settings › Content**, **Skip intro and credits buttons**, on by default, gives apps the intros, recaps and credits to skip; off, `/MediaSegments/{id}` lists none and no segment database is asked, as on a Jellyfin server without a segment provider. **Similar titles**, on by default, lists titles close to the one open; off, every Similar route answers an empty list and no addon catalog is read for it (an unknown title is still not found). **Marked played after (%)** and **Resume point kept after (%)** replace Jellyfin's MaxResumePct and MinResumePct: a position past the first marks the title played, one before the second keeps no resume point. They default to Jellyfin's 90 and 5; unlike Jellyfin, which takes any values, Polyfin keeps the first from 50 to 100 and the second from 0 to 50, and refuses a resume threshold that is not below the played one. A title shorter than 5 minutes is still played as soon as it is past the resume threshold, as in Jellyfin. Under **Settings › Catalogs**, **Keep version lists for (minutes)** (10 by default, from 1 to 360) sets how long a title's versions and subtitles from the addons are kept: longer sends fewer requests to the stream addon, which helps with providers that refuse too many, but new versions show up later. Preparing playback ahead readies the next episode a minute before that life ends, 9 minutes before the end of the episode at most and 1 at least. **Refresh catalogs every (minutes)** (10 by default, from 1 to 1,440) sets how long catalog pages are kept, the Live TV guide's included. Every change applies at once, to what is already kept too.

**Skip segments:** the skip buttons come from three community databases, asked about a title the first time an app asks for its segments: TheIntroDB, IntroDB and PublicMetaDB, preferred in that order unless `POLYFIN_SEGMENTS` gives another. For each kind of segment (intro, recap, credits, preview), the first database that has one gives it, so the others fill the gaps. **Order of the skip marker sources**, under **Settings › Content**, below the skip buttons, lists the three with arrows to move them, each marked on, needing a key (PublicMetaDB without one) or turned off by `POLYFIN_SEGMENTS`; the order saved there replaces the one `POLYFIN_SEGMENTS` gives, at once and for the answers already kept too, but not its choice of databases: one it leaves out is never asked, wherever it is. **Reset to the default order** follows `POLYFIN_SEGMENTS` again, and so does saving its own order. Their answers are kept 30 days when they found segments, a day when they found none, and an hour after a failure; a database that answers 429 with a `Retry-After` is asked about no title until then. PublicMetaDB also brings recap and preview markers, on episodes, along with intros and credits. It is asked only with an API key, created on PublicMetaDB under **Settings → API** and pasted in **PublicMetaDB key** under **Settings › Content**: Polyfin checks it with PublicMetaDB before saving it, and refuses one PublicMetaDB refuses or cannot be asked about. The key is never shown again, the page only telling that one is saved, nor logged; an empty field removes it. Saving, changing or removing the key applies at once, without a restart, and titles asked about before a key was saved are asked again once one is. Should PublicMetaDB refuse the key later, Polyfin logs it once and asks no more until another key is saved. PublicMetaDB knows titles by their TMDB identifier only (a movie's, or a series' with the season and episode numbers), and keeps one record per contributor and release: Polyfin uses the one of a streaming release giving the most segments, the latest first. **TheIntroDB key (optional)**, next to it, is a TheIntroDB API key: TheIntroDB answers without one, but with one its daily limit goes from 500 requests per address to 1,000 per account, and its answers include your own submissions, even pending ones, weighted more. It is checked, kept secret and applied at once like PublicMetaDB's. Should TheIntroDB refuse it later, Polyfin logs it once and keeps asking TheIntroDB without it until another key is saved.

**Security settings:** **Settings › Users and security** gathers three settings, and **Settings › Diagnostics** a fourth; they apply at once, without a restart. **Allow users' own addons**, on by default, lets users add addons of their own under **My addons**; under **Users**, each user also has their own **Can add their own addons** permission, on by default. While either is off, the user's own addons are kept but not used: their apps show the server's addons and libraries only, **My addons** says why, their addons cannot be added, replaced, refreshed or turned on (403 `personal_addons_disabled`), and they come back once both are on again. **Block an account after this many wrong passwords**, 0 (never) by default, or 3 to 20: after that many wrong passwords in a row for one account, from a Jellyfin app or the admin interface, the account refuses every sign-in for 15 minutes, the right password included, with the answer of a wrong password. A sign-in, a new password set by an administrator, or **Unblock** under **Users**, where the account shows until when it is blocked, starts the count again, and so does setting the limit to 0. Jellyfin apps read the limit (-1 when there is none) and the count in the user's policy, as `LoginAttemptsBeforeLockout` and `InvalidLoginAttemptCount`; the limit is the server's, so a policy an app posts does not change it, nor the count. Unlike Jellyfin, which disables the account until an administrator enables it again, Polyfin only blocks it for a while, so that the last administrator can never be locked out for good. **Sign out devices unused for**, 0 (never) by default, or 1 to 365 days: Polyfin signs out the Jellyfin apps not used for that many days, at startup and every hour, closing their connections and taking them out of SyncPlay groups as any sign-out does; admin interface sessions are not concerned. **Detailed log** (under **Diagnostics**), off by default, has Polyfin log at the `debug` level until it is turned off again, whatever `POLYFIN_LOG_LEVEL` says.

**User playback and access:** under **Users**, each user's **Playback and access** section holds five more limits, which administrators' Jellyfin apps also set from the user's settings. **Playbacks at once** (0, the default, for no limit, up to 20): once that many of the user's other devices are playing, as **Sessions** lists them, PlaybackInfo from one more device answers Jellyfin's `RateLimitExceeded`, which jellyfin-web explains as media that cannot be played at this time; a device already playing can go on to another title. Jellyfin's `MaxActiveSessions` counts signed-in sessions and refuses signing in; Polyfin counts playbacks instead, on purpose, so a user stays signed in on every device, and refuses a policy setting more than 20 (400). **Maximum quality** (no limit by default) caps the bitrate of everything the user plays: PlaybackInfo uses the lower of the app's limit and this one, converts a version above it down to it when the user may use conversion, else plays the next version under it, else nothing (`NoCompatibleStream`). A version above the limit is never played as it is or with its video copied, even from a kept or made-up URL. Jellyfin's `RemoteClientBitrateLimit` applies to remote apps only; Polyfin applies it, on purpose, to all of the user's playback. With **Live TV** off (it is on by default), the Live TV view leaves the user's apps, the `/LiveTv` routes answer 403 as Jellyfin's do without `EnableLiveTvAccess`, and channels and programmes can be neither found nor played. **Watch together** chooses, as Jellyfin's `SyncPlayAccess` does, whether the user may create and join SyncPlay groups (the default), only join them, or not watch together at all, in which case jellyfin-web hides its button: creating a group takes the first, listing and joining groups either of the first two, and other SyncPlay requests answer 403 unless the user is in a group. **Can control other users' apps** (Jellyfin's `EnableRemoteControlOfOtherUsers`) lets the user see and control the apps of other users from theirs; administrators have it when created and when upgrading from an older Polyfin, other users do not, and a user made administrator later keeps the value they had.

**Quality groups:** under **Users**, **Quality group** in **Playback and access**, next to the maximum quality, sets the highest resolution each user is offered: **Original** (the default, no limit), **4K**, **1440p**, **1080p**, **720p** or **480p**. Jellyfin has no such setting: apps neither show nor change it, and a policy they post keeps it. A version's height is the one its analysis found once Polyfin analyzed it, and before that the one its labels name, in the addon's stream name, title, description or file name (2160p, 4K or UHD; 1440p, 2K or QHD; 1080p or FHD; 720p or HD; 576p, 480p or SD); labels that disagree, or name none, leave its height unknown. Versions taller than the group are left out of what the user is offered and of the versions PlaybackInfo tries, and are not analyzed, while one version fits or has an unknown height; the others keep their order. When every version is taller, all are kept rather than none, the closest to the group first (720p before 1080p before 4K, versions of the same height in their order), so that the least is read and decoded, and the one played is converted down to the group, or to **Maximum quality of converted video** when that is lower (and to 1080p at most, as every conversion); a version that fits plays as it is or remuxed as before, while a taller one is never sent at full size, and PlaybackInfo reports its conversion as Jellyfin reports a resolution limit (`VideoResolutionNotSupported`), describing its video at the size sent. A user who may not have video converted (their **Can use conversion** permission, or the server's **Conversion** switch, off) is refused taller versions as other conversions are refused (`NoCompatibleStream`). Live TV channels follow the same rule once analyzed, as their height is only known then, and so do recordings. Only versions that fit can be downloaded, as downloads are never converted: when none fits, the download is refused (403) as without the permission.

**Playback choices:** five more settings, under **Settings › Playback** and **Settings › Conversion**, change how PlaybackInfo picks a version and how much video the server converts. Their defaults keep Polyfin as it was, and a change applies to the next request, without a restart. **Maximum time to analyze a version** (45 seconds by default, from 5 to 120) bounds every ffprobe analysis, of files and of live streams: a source that does not answer in time is given up for 15 minutes, and PlaybackInfo moves on to the next version sooner. **Versions tried when one does not work** (3 by default, from 1 to 10) is how many versions PlaybackInfo analyzes when the app picked none, for titles and channels alike; later versions analyzed before are still tried, as they cost nothing. **Prefer versions the app plays without conversion**, off by default, makes PlaybackInfo go on through those versions until one plays on the app as it is or remuxed with its tracks copied, and fall back to the first that plays at all when none does: the first play of a title may analyze more versions, and nothing changes once they are known. A version above the user's **Maximum quality** never counts as one that plays without conversion. Jellyfin 12.1 keeps the version opened first however it plays, as Polyfin does with the setting off. **Video conversions at once** (0 by default, no limit; up to 32) caps the playbacks whose video the server converts, burning subtitles in included, files and Live TV together; Live TV keeps its own caps of 4 channels per user and 16 for the server on top. A playback is what a user plays of a version, from its first converted segment until the app stops it or asks nothing for 3 minutes (1 for Live TV): its next segments, its seeks, and the new play session apps open to switch tracks never count again. At the cap, PlaybackInfo plans no new video conversion, as when conversion is off: it picks the next version that plays without one, else answers `NoCompatibleStream`. An HLS request that would start one more conversion answers 503, as when Live TV is at its cap. Jellyfin has no such cap: its nearest, a tuner's stream limit, fails with a 500, which apps take the same way, as a server error. **Maximum quality of converted video** (Original by default, or 480p to 2160p) scales converted video down to that height, keeping its shape, at the bitrate of that height; a running conversion keeps the size it started with, and files played as they are or with their tracks copied are untouched. Polyfin converts to 1080p at most, so 1440p and 2160p change nothing for now.

**Conversion settings:** **Settings › Conversion** also tunes how video and audio are converted, as Jellyfin's Transcoding page does, for files and Live TV alike (recordings copy the stream, and are converted like any file when played). Every default keeps Polyfin's conversions exactly as they were, and a change applies to the next playback, without a restart.

- **Graphics card used to convert:** the default follows `POLYFIN_HWACCEL`; **Automatic**, **NVIDIA (NVENC)**, **AMD or Intel (VAAPI)** or **None** overrides it once saved: the choice is detected then, once per choice, and playbacks already converting go on as they started. **Detected on this server** shows, read only, the card chosen with its device, its encoders, whether it tone maps HDR and, for VAAPI, whether it takes a quality number, and the processor's encoders and tone mapping. Options the hardware cannot do are disabled.
- **Read these formats on the graphics card:** H.264, HEVC, HEVC 10-bit (which needs HEVC), VP9, AV1, MPEG-2 and VC-1, all checked by default; an unchecked format is decoded by the processor, for conversions and thumbnails. Other formats are tried on the card, as before. Jellyfin checks only H.264 and VC-1 by default.
- **Encoding speed:** **Automatic** keeps Polyfin's (`veryfast` for x264 and x265, `p4` for NVENC, the driver's for VAAPI); **Very slow** to **Ultra fast** are x264's presets, mapped as Jellyfin maps them to NVENC's `p7` to `p1` and VAAPI's compression levels 1 to 7, which Jellyfin sets on Intel drivers only.
- **H.264 quality** and **HEVC quality** (0 by default, else 1 to 51): 0 aims for the bitrate alone, as before; a number is a quality factor the bitrate caps: CRF for x264 and x265, CQ for NVENC, and QVBR's quality for the VAAPI drivers that have it, others ignoring it. Jellyfin's are CRF 23 and 28 by default, and only for x264 and x265.
- **Allow converting to HEVC** (off by default): apps listing HEVC before H.264 get HEVC, as with Jellyfin's **Allow encoding in HEVC format**. Off, H.264 comes first and only apps that take no H.264 get HEVC, as before and as Jellyfin does.
- **Convert HDR to SDR** (on by default, as before; Jellyfin's is off): off, HDR is converted without tone mapping and looks pale, without the processor's 720p cap, and Dolby Vision without an HDR10 layer is not converted. **Tone mapping method**: **Automatic** (BT.2390 on the card, Hable on the processor, as before), BT.2390 (card only: the processor's filter has none, and uses Hable), Hable, Reinhard, Möbius, Clip or Linear. **Peak brightness** (0, the video's, or 100 to 10,000 nits) and **Highlight desaturation** (0 to 10) apply on the processor only, as libplacebo on the card takes neither; Jellyfin's peak is 100 by default.
- **Deinterlacing method**: Yadif (the default) or Bwdif; **Double the frame rate** makes a frame of each field of video up to 30 frames a second, as Jellyfin does.
- **Mix to stereo**: FFmpeg's own (the default) or Jellyfin's Dave750, Night mode, RFC 7845 and AC-4, for the layouts Jellyfin lists for each, 5.1 and 7.1 among them; **Volume when mixing to stereo** (0.5 to 3, 1 by default; Jellyfin's is 2). **Most audio channels** (as many as the app takes, mono, stereo or 5.1) and **Audio bitrate per channel** (0 for Polyfin's 192 kb/s in stereo and 64 kb/s a channel above, or 32 to 320 kb/s) shape converted audio; Jellyfin has neither.
- **Processor threads per conversion** (0, FFmpeg's choice, to 64) is Jellyfin's encoding thread count. **Segments prepared ahead** (10 by default, from 1 to 60) is how many segments of about 6 seconds a remux or conversion of a file makes past the last one the app asked for before it waits; Jellyfin throttles by seconds, and not by default.

**User content:** under **Users**, each user has three more settings, which administrators' Jellyfin apps can also set from their user pages. **Visible libraries** chooses which of the server's libraries the user's apps show: all of them by default, and libraries added later show. It only chooses the libraries shown and blocks no title: a hidden library's titles stay reachable through other libraries, search or links, and listing the library itself is refused as Jellyfin refuses a folder the user may not access (401). Parental control and blocked genres are what block titles. Apps read and set it as the policy's `EnableAllFolders` and `EnabledFolders`; Jellyfin keeps the libraries shown, while Polyfin keeps those hidden, so that a library added later shows even when an app chose the libraries. **Blocked genres** hides the titles of any of these genres, in any letter case, everywhere parental control hides titles: lists, search, details, playback, downloads, Continue Watching, Next Up, similar titles and person pages. A title's genres are those the server's addons give in its complete description, looked up and kept like its rating; a title is hidden until they are known, and a user who blocks genres browses the server's addons only, as under parental control. The admin app offers the genres of the server's libraries, those their genre pages are named after, or any genre typed. Jellyfin has no such setting: its `BlockedTags` are tags, which Polyfin's titles do not have, so the policy reports none and Polyfin ignores those apps send. **Allowed hours** are Jellyfin's access schedules: rows of a day (one day of the week, every day, weekdays or weekends) and a start and end hour from 0 to 24, both included, in the server's time zone. A user with at least one row, outside all of them, cannot sign in (403), and their apps' requests are refused with an empty 403, as Jellyfin does, except reading their own user and the server's information. As in Jellyfin, administrators are refused sign-in outside their hours, but their apps signed in already are served, and a Quick Connect sign-in is not checked, though the app's requests then are. Unlike Jellyfin, which serves direct streams without checking who asks, Polyfin also refuses a user's media outside their hours, and it refuses hours outside 0 to 24 or ending before they start, which jellyfin-web never sends. In the admin app, nobody signs in outside their hours, and a member already signed in sees only who they are.

**Live TV guide (XMLTV):** some IPTV addons publish no Native EPG guide, while their provider publishes one as an XMLTV file. Each TV catalog shown under **Libraries**, or under **My addons** for a user's own, can take such guides once the libraries are saved: up to 10, in order, from its guide page, the first of which its row shows. An address may hold the provider's credentials: like manifest URLs, it is never shown in full, and only administrators can use one on a local network address. Polyfin fetches a guide when its address is saved, again once **Refresh Live TV lists and guides every** hours have passed (under **Settings › Live TV**: 12 by default, as before the setting, from 1 to 168; the guides due are looked for every 30 minutes), and when **Refresh guide** is pressed, which fetches every guide of the catalog; the catalog's row then shows when its first guide was last fetched, when it will be fetched next, how many of its channels are mapped to a guide channel, and why the last fetch failed, if it did, and its guide page shows the same for each guide with the channels and programmes it held. The file may be plain XML, compressed with gzip, or a ZIP archive (told by its content, not its name), up to 300 MB downloaded and four times as much once uncompressed. Plain and gzip guides are read as they arrive, never whole; a ZIP archive, which can only be read once complete, is first written to a temporary file in Polyfin's cache folder (`POLYFIN_CACHE_DIR`), removed as soon as it is read or fails, and its `.xml` file, the largest if it holds several, is then read the same way; an archive without one is reported as not a guide. The download must answer within 30 seconds, never stall for a minute and end within 10 minutes. A guide channel whose identifier is the channel's Stremio ID, or, for a channel of an IPTV source, the channel's own guide identifier (its list's `tvg-id` or `epg_channel_id`), takes it. Lists often write that identifier in another case, or with a feed after an `@` (`Name.fr@SD`): failing an exact match, a guide channel whose identifier is the same ignoring case, then one equal to the part before the last `@`, exactly and then ignoring case, takes it, before any name, with ties ranked by country and then programmes as below. Otherwise its display names are compared with the channel's name once HTML entities left in them are decoded and case, accents, punctuation, separators such as "|", list prefixes such as "FR:", "FR|" or "KIDS|", and marker characters such as ᴴᴰ or ★ are set aside: an exact match keeps quality tags such as HD, FHD, UHD, 4K or SD, a loose one sets them aside too. Many guides list the same channel for several countries, so the candidates are ranked: first those of the channel's own country, the one its prefix names ("FR:"), else the one the server language suggests (France for French; none for English), a guide channel's countries being those of its identifier ("Name.fr") and of its display names' prefixes ("FR|"); then exact matches before loose ones; then the catalog's guide listed first; then, within a guide, the guide channel with the most distinct programme titles in the window kept, so that a placeholder repeating one title ("No Data", or "Name 4K" advertising itself) loses to a real guide; then the first one listed. Each channel takes one guide channel, and several channels, such as a channel and its timeshift copy, may share one. A download keeps the guide's channels, with their names and icons (a channel its programmes name without declaring it counts as one without a name), and its programmes from a day before the fetch to eight days after it, with their title, episode title, description, categories, season and episode numbers and image; a failed fetch keeps those of the last one. Channels are then mapped again from what is kept, without downloading: after every download, list refresh and change of an IPTV source's options, and from the guide page, where **Map unmapped channels** maps only the channels without a mapping and **Map all again** remaps every channel. The guide page also lists the catalog's channels with their mapping (all, mapped, unmapped or set by hand) and searches the guides' channels by name or identifier, showing what each airs now, to map a channel by hand, or to no guide at all; such a choice survives downloads, refreshes and **Map unmapped channels**, only **Map all again** or clearing it returns the channel to automatic mapping. A guide removed takes its mappings with it. They appear wherever Native EPG programmes do (the programme listings, recommended programmes, a programme's details and the programme each channel airs now), with the same filters, and a guide category such as "Movie", "News" or "Sports" marks programmes as a Native EPG genre does. A channel with Native EPG programmes keeps them: the XMLTV guide only fills the channels without. Unlike Jellyfin, whose XMLTV guides belong to its tuner setup, Polyfin attaches a guide to a TV catalog. Programmes from either guide now also give apps their episode title and their season and episode numbers, as Jellyfin's do; `/LiveTv/GuideInfo` still answers the seven days Jellyfin's guide spans.

**IPTV sources:** an M3U playlist or an Xtream Codes account can be imported directly, without a Stremio addon: **Add an IPTV source**, under **Addons** for the server or **My addons** for a user's own, under the same rules as addons (a user's own sources follow **Allow users' own addons** and the user's **Can add their own addons**, and only an administrator's may reach a local network address). A source takes a name; for M3U, the playlist's address; for Xtream Codes, the server's address, a username and a password; and, optionally, the address of an XMLTV guide, which for Xtream Codes is by default the one the server publishes for the account. The list is downloaded when the source is added (a list that cannot be read is not added), again with the guides once **Refresh Live TV lists and guides every** hours have passed, and when **Refresh** is pressed on the source's row; a download that fails keeps the previous channels and tells why. Lists are read as they arrive, up to 100 MB and 100,000 channels. A playlist's `#EXTINF` lines give each channel its `tvg-id`, `tvg-name`, `tvg-logo`, `tvg-chno` and `group-title` (quoted with double or single quotes, or not) and its name after the comma, and its `#EXTVLCOPT` `http-user-agent` and `http-referrer` lines the headers its stream is requested with; a byte order mark, CRLF line ends and `#EXTGRP` lines are accepted. An Xtream Codes account is read through its player API (its live categories and streams); its channels stream in MPEG-TS, or HLS when the account only allows HLS. Headings that lists put between channels are skipped: names without a letter or digit, or drawn with a run of three or more decoration characters, such as `##### NAME #####` or `=== NAME ===`. **Import options**, chosen when the source is added (with a preview of the list's groups or countries and their numbers of channels, a list it downloads once for the next few minutes) and changed later, turn the list into the source's line-up: **Categories** from the provider's groups (by default) or one per country, told by the group's name first and then the channel's (a flag, or a prefix such as `FR|`, `[FR]`, `(FR)`, `FR:` or `FR -`; `UK` counts as GB; the rest under Other, last); **Channels** one per entry (by default) or merged, the entries of a category with the same name once country prefixes and quality tags are set aside becoming one channel with a stream per entry, best quality first (4K, UHD, FHD, HD, SD, then the others); the groups and countries **left out**; whether **new channels** found by a refresh arrive turned on (by default) or off; and the **numbering**, the list's number (`tvg-chno`, or Xtream's `num`; by default) or none, apps then numbering channels by their place. Polyfin keeps the line-up and reconciles it with the list on every download and option change by stable keys (a category by its group or country, a channel by its entry, or by its category and name when merged, and by any of its former streams when the mode changes): the administrator's edits stay, the provider's names, logos, numbers and guide identifiers update underneath, and what the list dropped or the options now leave out goes away with its edits. The source's line-up page edits categories (add, rename, reorder, turn on or off, and delete the added ones, whose channels go back to their own) and channels (turn on or off, rename, change the logo or description, move to another category or place, fix a number, and reorder, turn off or add streams), one by one or in bulk, by selection, category or keyword, with a count of what would change first; its lists are paged and searched by the server, so that line-ups of tens of thousands of channels stay quick. Apps list the turned-on channels of turned-on categories that have a turned-on stream, in category then channel order, their category being their genre, and **Channels read per Live TV catalog** counts those only. A merged channel's details offer one version per turned-on stream, best first; playing it tries them in order, as many as **Versions tried when one does not work**, past those that fail, among those that fit the user's quality group (unlike Jellyfin, whose tuner channels each have one source, so that apps offer the streams as a version choice). An added stream's address follows the source's rule for local network addresses and is never shown in full. A source behaves as an installed addon with one TV catalog: it is listed, ordered, turned off and removed with the addons, its catalog is enabled under **Libraries**, where its guide panel is, whatever the number of libraries, and its channels play, record and follow the Live TV permission, quality groups, parental control and allowed hours as any channel. **Edit** on its row renames it and changes its address or login (fetched first; a password left empty keeps the current one); a channel no longer in the line-up, or turned off, is no longer listed nor played. A source added before line-ups keeps what it showed: the groups it did not show become turned-off categories. **Movies and series:** besides **Live TV channels** (on by default), a source can import the provider's **Movies** and **Series** (both off by default, which keeps a source exactly as before: an M3U playlist's movies and episodes then stay channels). Their categories are chosen from a preview counting each one's titles (search, include all, exclude all), as the line-up's groups are, a category added later by the provider being imported; and their libraries are **one per type** (by default: a Movies and a Series library named after the source, each title's category being its genre, by which the library can be narrowed) or **one per category**. An Xtream Codes account's VOD and series lists are read through its player API (`get_vod_categories`, `get_vod_streams`, `get_series_categories`, `get_series`) with its live list, only for the types turned on; turning a type on reads its list at once. An M3U playlist's entries are movies or episodes by their address (a `/movie/` or `/series/` path) or their video file's extension (`mp4`, `mkv`, `avi` and the like; `ts` and `m3u8` stay live); an episode's name gives its series, season and episode (`S01E02`, `S01 E02`, `1x02`, `Season 1 Episode 2`), episodes whose names give no numbers being numbered by their place, and episodes group into series by name whatever its case. Titles are named without the list's dressing (a language or country prefix such as `EN -` or `|FR|`, quality tags), the year written after a name becoming the title's year, and keep the provider's identifier, so that their item identifiers, and with them users' played state, resume points, favorites and next up, survive refreshes, changes of order and new credentials. The libraries are ordinary library rows of the source: a catalog that appears is added as an enabled library at the end of the scope's libraries, one that goes away loses its library, and a library turned off under **Libraries** stays off; with **Live TV channels** turned off the source has no Live TV catalog (its guides are removed) while its line-up keeps its edits for when they come back. Movies and series are ordinary titles in apps (details, search, latest, genres, continue watching, next up, collections), newest first in their libraries, which are paged and counted whole (**Titles read per movie and series catalog** does not bound them: they are stored, not asked of an addon page by page). Listings use only the lists' data: an Xtream title's details (`get_vod_info`: overview, cast, director, genres, release date, duration, backdrop, trailer, TMDB id; `get_series_info`: seasons and episodes) are asked only when an app opens the title or plays it, kept until the series changes or for seven days, and asked of a provider host at most once a second, as providers ban accounts that send bursts. Each movie or episode has one version, the provider's file (`/movie/…` or `/series/…` with its container for Xtream), labelled with the quality its name gives (4K, FHD, HD, SD) for quality groups, and plays, converts, downloads and takes thumbnails and subtitles as any title's. An MPEG-TS file, which has no index to cut it by its keyframes, plays as it is on apps that take MPEG-TS and otherwise only converted, as Jellyfin plays such files: cut every six seconds over its duration, FFmpeg reading it from the time an app seeks to, the encoder placing a keyframe at each segment's start; a user who may not have video converted is told no stream suits instead (this holds for addons' MPEG-TS files too). Providers give no content rating: titles are unrated (a user blocking unrated movies or series does not see them) unless enrichment brings one. With enrichment, an import option (on by default: it only asks the administrator's own addons, once per title opened, and brings the posters, cast and age ratings the providers lack), a title the provider gives a TMDB or IMDb identifier is described by the first of the user's addons that describes that identifier, the provider's description filling what it lacks; the title's name, category and episodes stay the provider's. Addresses and logins are stored as manifest URLs are, never shown in full (only the server's scheme and host) and never logged. Catch-up and connection limits are not handled.

**Collections:** users who may manage collections group titles into collections from their apps, as Jellyfin's BoxSets (**Add to collection** in jellyfin-web): movies, series, seasons, episodes, an addon's collections and Live TV channels. Collections belong to the server: once one exists, every user's apps show a **Collections** view (CollectionType `boxsets`) listing them by name, a listing of BoxSets across the server lists them too, and a library's Collections tab lists those holding a title from it. Each user sees only the titles they may see: those that parental control or blocked genres hide neither show in a collection nor count in its ChildCount, RecursiveItemCount or played count, and allowed hours apply as everywhere. As in Jellyfin, a collection lists its titles by premiere date and takes their genres, their least restrictive rating and the earliest premiere date; played as a whole, a series brings its released episodes. Its poster is that of the first title the user sees (an episode shows its series' poster), as their listing tags it; without a tag, its first title's. Nothing else is looked up for a collection: Jellyfin's IsLocked is kept as apps send it. Under **Users**, the **Access** section's **Can manage collections** permission (Jellyfin's `EnableCollectionManagement`, which administrators' apps also set from the user's policy) is on for administrators, existing ones included, and off for other users. Without it, `POST /Collections` and `POST` or `DELETE /Collections/{id}/Items` answer an empty 403, as in Jellyfin, administrators included. A collection is deleted as Jellyfin deletes one, with `DELETE /Items/{id}`, which administrators and users who may manage collections may do; others get 401. Unlike Jellyfin: a collection none of whose titles a user may see still shows to them, empty, where Jellyfin hides it; a collection needs a name, and the titles added must be ones the user adding them may see, else the request answers 400 and changes nothing, where Jellyfin creates the collection and then fails (with a 500 for a missing name or an identifier that is not one); collections hold no people, programmes or other users' collections; and the Collections view is not among the visible libraries an administrator chooses, as the Playlists view is not.
**Administration and integrations:** **API keys** (admin app, or jellyfin-web's dashboard through `/Auth/Keys`) let tools such as request managers use the Jellyfin API as Jellyfin's keys do: the key goes as the token of the Authorization header or the `ApiKey` query parameter (`api_key` and `X-Emby-Token` only with legacy authorization), with administrator rights and no user. Requests that name a user (`userId`, `/Users/{id}/…`) act for that user, whose parental control, blocked genres, visible libraries and allowed hours apply; without one they see the server's libraries, and `/Users/Me` answers 400 as in Jellyfin. Polyfin stores only a hash of each key, with its app name, creation date and last use: the admin app shows a key once, and `/Auth/Keys` lists a key made from a Jellyfin app in full only on the next listing, then its identifier, which `DELETE /Auth/Keys/{key}` accepts as well as the key. A key cannot open a WebSocket. Administrators also get Jellyfin's devices (`/Devices`, with custom names; deleting a device signs out every user on it), user creation, renaming and deletion from jellyfin-web (with Polyfin's rules: a password of at least 8 characters is required, unlike Jellyfin, and the last administrator stays), `/Library/MediaFolders`, the server configuration (`/System/Configuration` answers Polyfin's server name, language, resume thresholds, Quick Connect and legacy authorization, with Jellyfin's defaults for the rest; saving applies those fields only and keeps those left out), storage (`/System/Info/Storage`: the cache folder and, when `POLYFIN_RECORDINGS_DIR` is set, the recordings folder), the authentication providers, and the activity log, which records sign-ins and failed ones, playback start and stop, users created, changed or deleted, settings saved and addons installed or removed, keeps 30 days and shows its last entries on the admin app's Status page. `/System/Logs` serves the last 5 MB of the log as one file, `polyfin.log`, kept in memory with URLs reduced to their host and tokens, keys and passwords replaced; apps' uploaded logs (`/ClientLog/Document`, 1 MB at most) go to the log, redacted the same way. `/ScheduledTasks` shows Polyfin's own jobs (signing out unused devices hourly, cleaning the activity log daily, fetching the IPTV channel lists and then the Live TV guides due under **Settings › Live TV**, looked for every 30 minutes, or every list and guide when started by hand, and refreshing ratings, which asks addons and runs only when started) and lets them be started and stopped; their schedules cannot be changed (400). **Forgotten password:** a user on the local network asks for a PIN from the app's sign-in screen; the PIN, valid 30 minutes, is logged and shown on the admin app's **Users** page, as there is no server file to read it from. Entering it in the app makes it the user's password and signs them out everywhere; wrong PINs count as failed sign-ins. Asked from outside the local network, the answer is the same and no PIN is made, as in Jellyfin.
**Live TV recordings:** Polyfin records Live TV programmes, as Jellyfin's DVR does, once `POLYFIN_RECORDINGS_DIR` names a folder it can write to (see Configuration; Polyfin does not start with one it cannot use). Without it, recording is off and Polyfin answers as a server that records nothing: the recording, timer and series timer lists stay empty, what they would hold is not found, and new timers are refused (400). Under **Users**, **Can record Live TV** at the end of **Playback and access** is Jellyfin's `EnableLiveTvManagement`, which apps also read and set in the user's policy: on for administrators, off for other users by default. It lets a user schedule, change and cancel recordings and delete them (403 otherwise, as Jellyfin answers); seeing them needs Live TV only. From a programme of the guide, apps make a timer, which records that programme, or a series timer, which records every programme of the same title in the guide, on the same channel at the same time of day (within ten minutes) unless it records on any channel or at any time, as Jellyfin's do. The guide marks no repeats, so "new episodes only" records every one, and, like Jellyfin, the days of the week a series timer lists are not looked at; **Keep up to** deletes a series' oldest recordings past that many. Guide programmes show their timers (`TimerId`, `SeriesTimerId`). Timers, series timers and recordings are kept in the database. A recording starts **Start recordings early** minutes before its programme and goes on **Keep recording after the end** minutes after it (under **Settings › Recordings**, none by default, as in Jellyfin, from 0 to 60; apps can change them per timer). FFmpeg copies the channel's stream, read as live playback reads it, with the headers it needs and within its addon's confinement, from the guide of the user who scheduled it. It counts among that user's 4 channels played through FFmpeg at once, and the server's 16: past the user's 4, it takes the place of their oldest channel watched, and a channel watched never takes the place of a recording. A stream that stops before the end is read again 30 seconds later. While it records, the file is written in MPEG-TS, which apps can follow at `/LiveTv/LiveRecordings/{id}/stream`; once the programme ends, it becomes one Matroska file in the folder, which plays like a movie's version: as it is, or remuxed into HLS. A recording under way when Polyfin stops is kept as a partial recording when it starts again, and the rest of the programme, if it still airs, is recorded as another. **Keep recordings for** (0, forever, by default, up to 3,650 days) deletes older recordings once a day. Recordings are listed, newest first, under `/LiveTv/Recordings` and in a **Recordings** folder (`/LiveTv/Recordings/Folders`), to the users who reach the channel they come from and to the user who scheduled them; parental control and blocked genres apply to them as to titles (Jellyfin judges recorded videos as "Other" items), and to the programmes users schedule ("LiveTvProgram"). Unlike Jellyfin: a recording plays through PlaybackInfo only once finished; `/LiveTv/LiveRecordings/{id}/stream` needs a signed-in user's credentials or play session, like Polyfin's other media; a timer or series timer asked for a programme Polyfin does not know answers 404 (`Timers/Defaults`) or 400 (`SeriesTimers`) where Jellyfin fails with 500; `POST /LiveTv/Timers/{id}` changes the timer the route names, not the one in the body; Jellyfin's `IsPrePaddingRequired` and `IsPostPaddingRequired` are not kept; and its keep-until choices are kept but only **Keep recordings for** and **Keep up to** delete recordings.

**Dashboard features Polyfin does without:** plugins, packages and plugin repositories, browsing the server's folders, library folders and metadata providers, Live TV tuners and listing providers, the startup wizard and backups answer as a Jellyfin 12.1 on which nothing of the kind is configured, to administrators only where Jellyfin requires one: `/Plugins`, `/Packages`, `/Repositories`, `/Environment/Drives` and `/Environment/DirectoryContents`, `/Library/PhysicalPaths`, `/LiveTv/Tuners/Discover`, `/LiveTv/TunerHosts/Types` and `/Backup` list nothing; `/Libraries/AvailableOptions` lists no provider (Jellyfin also lists its own, its NFO reader and saver among them); `/System/Configuration/MetadataOptions/Default` and `/LiveTv/ListingProviders/Default` are Jellyfin's defaults; `/Startup/Configuration` and `/Startup/User` show the server name, language and earliest administrator, setup being always complete. Writes are refused as Jellyfin refuses them for what does not exist (an unknown plugin or package, path, tuner, listing provider or backup), and those Jellyfin would perform answer 403: saving plugin repositories, creating a backup, and the wizard's configuration, remote access and first user (change the server's settings in the admin app or through `/System/Configuration`). Polyfin never shows the host's folders: `/Environment/ValidatePath` answers 404 for every path.

**Editing items:** administrators can use jellyfin-web's **Edit metadata**, **Edit images** and **Identify** on the items apps show: titles, seasons, episodes, people, channels, music, libraries, views, collections and playlists. Polyfin keeps what they change apart from what the addons say, and it wins for every user, wherever the item shows: details, listings, search (a title renamed is also found by its new name) and parental control, which judges a title by the custom rating set, else the official rating, and by the genres set, as Jellyfin does. A series' name and ratings show on its seasons and episodes. Polyfin keeps the name, original title, sort name, overview, tagline, genres, tags, studios, official and custom ratings, community and critic ratings, premiere and end dates and production year. A field left empty, or set back to the addon's value, follows the addon again, so the addon's later changes show. People, provider identifiers and the editor's other fields (locks, display order, content type, date added) are not kept: they stay the addons'. **Edit images** has no image provider to search, as on a Jellyfin without one; it uploads a Primary, Backdrop, Logo, Thumb or Banner image in place of the addon's: a JPEG, PNG or WebP picture of up to 10 MB, scaled down to 3,840 pixels and kept in the database as profile pictures are. Other image types, and a body that is not such a picture, are refused with 400, where Jellyfin keeps any file as sent. Deleting an upload shows the addon's image again; the addon's own artwork cannot be deleted. **Identify** searches the server's addons that describe titles by name, for movies and series, and finds nothing for other types; applying a result fails, as a failed identification does in Jellyfin (500), because an item is its addon's title and cannot be bound to another. Apps also get the user's root folder (`/Items/Root`, whose children are the user's views), item counts (`/Items/Counts`: each library's first page of titles, plus one when more follow, as genre and studio pages count; the user's favorites exactly with `isFavorite=true`) and suggestions (`/Items/Suggestions`: titles picked at random among the first page of each library, where Jellyfin picks among everything).

**More for apps:** Jellyfin apps get the rest of what they ask a movie, series and Live TV server for. **Profile pictures**: a user changes their own from their app, an administrator anyone's (`/UserImage`, and the older `/Users/{id}/Images/{type}`); Polyfin keeps a JPEG, PNG or WebP picture of up to 5 MB in the database, scaled down to 512 pixels and stored as JPEG (PNG when it is transparent), shows it in users, sign-in screens and sessions, and on the **Users** page. **Search hints** (`/Search/Hints`) answer from the same search as `/Items`: the movies and series the addons find, then the episodes Polyfin knows by name from series already opened (addons search titles, not episodes), then the people credited in titles the user reaches, all within the user's libraries, parental control and blocked genres; Jellyfin ranks every kind together, Polyfin keeps that order. **Movie recommendations** (`/Movies/Recommendations`) give, for each of the last movies the user played, the "Because you watched" titles similar to it, from the similar titles of title pages and without those already played; Jellyfin's categories for liked titles and for the people of recent movies, which would each cost a search of the addons, are left out, and with **Similar titles** off there are none. `/Years` lists the years the year pages offer (catalogs whose genre filter offers years), `/UserViews/GroupingOptions` the movie and series libraries, `/Items/{id}/Images` a title's artwork, and `/Sessions/Viewing` records the item an app shows, which **Sessions** gives as `NowViewingItem`. Trailer items, plugin channels and theme songs and videos answer empty lists, as on a Jellyfin server without them: addons give trailers only with their titles. Sources need no opening, so `/LiveStreams/Open` answers 400 as Jellyfin does without an open token, and `/LiveStreams/Close` 204. `/Items/{id}/File` serves a title's first working version as the download route does, under the same permissions, which Jellyfin does not ask for its own files. **Fallback fonts** (`/FallbackFont/Fonts`) are the fonts of `POLYFIN_FONTS_DIR`, folders within included, where Jellyfin reads only the top of its folder; the image ships DejaVu (Latin, Greek and Cyrillic), mount more fonts there for other scripts, e.g. CJK. **Subtitle files**: under **Users**, the new **Can manage subtitles** permission (Jellyfin's `EnableSubtitleManagement`, also set from administrators' apps) is on for administrators and off for other users; it lets a user add an SRT, WebVTT, ASS or SSA file to a movie or an episode from their app (`POST /Videos/{id}/Subtitles`), which every version then offers first among its subtitles, and only administrators delete such files (`DELETE /Videos/{id}/Subtitles/{index}`), as in Jellyfin; addon subtitles and tracks inside files cannot be deleted (400). The subtitle search stays open to every user, unlike Jellyfin's, as it lists only what every version already offers; apps show it only with the permission. **Refresh metadata** (`POST /Items/{id}/Refresh`, administrators) makes Polyfin forget the title's description, version and subtitle lists and the rating it looked up, and ask the addons for the description again at once.

**Thumbnails:** **Settings › Thumbnails** makes Jellyfin's scrubbing thumbnails (trickplay) and chapter images, both off by default, because both read parts of the source. They are made after watching, at a gentle pace: once a version has been played, and for the next episode when playback is prepared in advance, Polyfin waits until that playback has stopped and nobody plays anything from the same host, then reads in the background only keyframes, located through the file's index (Matroska Cues or MP4 sample tables), each with a request for its own bytes, never the whole file. A version takes at most 60 requests, its index included, sent one every 3 seconds and at most 120 an hour per host, across versions: past that hour's share, they wait. The keyframes read are spread evenly over the runtime, and every thumbnail, one every **One thumbnail every** seconds (10 by default, from 5 to 60), shows the keyframe read nearest its time, so long movies get coarser thumbnails, a few minutes apart rather than a few seconds; chapter images share the same reads, the keyframe read nearest each chapter's start. A request answered oddly, as some hosts do now and then (the whole file for a range, another range, an answer cut short, or none), is asked once more after a short pause, counted in the budget; a link the source says expired is renewed, once a version, then asked again; two odd answers in a row fail the version for 30 minutes, and the log tells what the source answered, never its address. A host that asks to slow down (429) or fails as overloaded (502, 503, 504) is never asked again: it stops the version at once, nothing of it is kept, the version waits a day, and that host gets no image request for 2 hours, while other hosts go on; a version that fails otherwise is left alone for 30 minutes, or a day when its file cannot give images (no index, an unsupported codec). One version is made at a time, with a short queue. FFmpeg decodes each keyframe on its own as it arrives, tied to its time whatever the order it was read in, on the GPU when there is one, tone maps HDR, and the thumbnails, **Thumbnail width** wide (240, 320 by default, or 480), are packed into Jellyfin's 10x10 tile JPEGs; chapter images are at most 640 pixels wide. Those made by Polyfin 0.7.0, which could show their keyframes out of order, are dropped on upgrade and made again on the next play. Both are kept in the database: past **Space for images** (2 GB by default, from 1 to 50), the versions whose images were used longest ago lose them, and get them again on their next play. Apps get them as Jellyfin gives them: the item's `Trickplay` field by media source and width, keyed as the item's `MediaSources` name the versions (the first under the title's own identifier) and limited to the versions the user is offered under their quality group, `/Videos/{itemId}/Trickplay/{width}/tiles.m3u8` and `{index}.jpg`, which follow parental control, blocked genres and allowed hours, and chapters' `ImageTag`, served by `/Items/{itemId}/Images/Chapter/{index}` without credentials, like all images. Differences: thumbnails are of the keyframes read, so one may show a moment a few seconds, or on long movies a few minutes, from its time; chapters carry no `ImagePath`; and turning either setting off hides what was made, which shows again when it is turned back on.

**GPU:** at startup Polyfin encodes a few frames on each GPU it can reach, NVIDIA first, then AMD or Intel, unless **Settings › Conversion** or `POLYFIN_HWACCEL` chooses one, and logs the one it converts video on. Give the container an NVIDIA GPU with `--runtime=nvidia` (Compose: `runtime: nvidia`), which needs the NVIDIA Container Toolkit, or Unraid's Nvidia Driver plugin; give it an AMD or Intel GPU with `--device /dev/dri` (Compose: `devices`). On an NVIDIA GPU, HDR is also tone mapped there, through Vulkan, which needs `graphics` among `NVIDIA_DRIVER_CAPABILITIES`, as the image sets them. The container runs as user 65532: when the render nodes in `/dev/dri` are not open to every user, add the group that owns them with `--group-add`.

**Dashboard:** the admin app at `/admin/` opens on an **Overview** for administrators: what plays now (user, device and app, title, position, and how it plays: direct play, remux or conversion with Jellyfin's reasons, the user's quality group, the resolution and bitrate sent, and whether the GPU or the CPU encodes), updated every 3 seconds, then the activity log, filterable by kind. An administrator can stop a playback or show a message on its app when the app accepts remote control, as Jellyfin's remote control does; one whose **Can control other users' apps** permission was taken away is refused. **Schedule** lists the tasks with their last run, result, duration and next run, to run or stop by hand, the upcoming Live TV recordings, and when the IPTV lists and guides are fetched again. **Health** puts problems first, then the addons (from the requests made for apps since start: last answer, last failure, response time; **Check** asks an addon for its manifest once, at most once a minute, reaching only public addresses for a member's own addon), IPTV sources, guides, the transcoder (GPU, encoders, conversions against the limit), the database and its size, the source cache against `POLYFIN_CACHE_SIZE`, disk space for the cache and recordings folders, the thumbnail queue and paused hosts, and Polyfin's memory, goroutines, uptime and version; it sends no request outside the server. Schedule and Health cover the server's addons, IPTV sources and guides first, then those users keep under **My addons**, each marked with its owner, and their problems count in the summary. **Logs** follows the in-memory log, redacted as for Jellyfin apps, with a level filter, search and download. **Settings** is split into sections with a search box, and ends with the `POLYFIN_*` variables in effect, read only: secrets are hidden and the database URL shows its host and database only. A **Web player** link appears when the server serves one. None of these pages exist in Jellyfin's API: they use Polyfin's admin API only.

**IPTV line-up page:** adding an IPTV source takes two steps in the admin app: the account, then its categories, previewed by group or by country with their channel counts, to include or leave out, with the import options (categories by group or by country, quality variants merged or not, new channels turned on or not, the provider's numbers or the line-up's order). Each source then has its own page, opened from **Open the source** on its row under **Addons** or **My addons**, with six sections: **Summary** (counts, last and next download, **Download again**), **Import options** (the same choices, applied to the list already downloaded), **Categories** (order by drag and drop or arrows, on or off, rename, your own categories), **Channels** (a list read a page of 100 at a time from the server, filtered by category, state, visibility in apps and guide, with on/off switches, a selection to turn on or off, **Change by keyword** after a count, moves within a category, and an editor for the name, logo, description, category, fixed number, streams and guide), **Guides** (the catalog's XMLTV guides in order, with their status and the automatic mapping) and **Guide mapping** (the guide channel each channel takes its programmes from, set by hand from a search across the guides showing what airs now). A Stremio addon's Live TV catalog has the same **Guides** and **Guide mapping** views, from **Guides and mapping** on its row under **Libraries**.

**IPTV movies and series in the admin app:** the add flow's second step starts with **What to import** (Live TV channels, Movies, Series). With movies or series on, it shows their categories per type, with title counts and search, to include or leave out; the libraries choice (one Movies and one Series library, or one per provider category); and whether titles are described by the metadata addons. The source page, now titled **IPTV source** (its addresses do not change), has the same choices under **Import options** and the movies and series counts on its **Summary**. While Live TV is off, its four sections are hidden. The movies and series libraries are ordinary rows under **Libraries**, with a link to the source's import options.

**Unraid:** the template lives in [`templates/unraid/polyfin.xml`](templates/unraid/polyfin.xml) and needs a PostgreSQL 18 container. To add it, run in Unraid's terminal `wget -O /boot/config/plugins/dockerMan/templates-user/my-Polyfin.xml https://raw.githubusercontent.com/moodiness/polyfin/main/templates/unraid/polyfin.xml`, then choose **Polyfin** under **Docker › Add Container › Template**.

**Web client:** the Docker image includes jellyfin-web 12.1, Jellyfin's own web client, which Polyfin serves at `/web/` as Jellyfin does; it connects to the server that served it, as on Jellyfin. Once an administrator exists, `http://<server>:8096/` opens it; before, `/` and `/web/` lead to the setup page in the admin app, since no account could sign in yet (Jellyfin's web client opens its startup wizard then). Its **Dashboard**, from the menu or the user menu, and every dashboard page, the metadata manager, plugin pages and the startup wizard, open Polyfin's admin app at `/admin/` instead: Polyfin adds to jellyfin-web's page one script of its own, `/web/polyfin.js`, which follows the client's routes, and changes none of jellyfin-web's files. An administrator signed in to the web client arrives signed in: without a session, the admin app hands the access token the web client keeps in the browser for this server to `POST /admin/api/session/jellyfin`, in the `Authorization` header only, never in the URL. It opens an admin session, logged as a sign-in, only for the signed-in device of an administrator who may sign in now: not for an API key, which has no user, nor a disabled or blocked account, nor outside the account's allowed hours; an unknown token counts as a wrong password toward the client's failed attempts. It is tried once each time the admin app is opened, so signing out of it holds until then; other users get the sign-in page. The page itself is never cached, and files whose name or query carries a build hash are cached for a year; the other files are revalidated, where Jellyfin sends no caching header and leaves browsers to guess. `/web/` gets no Content-Security-Policy, as from Jellyfin: the admin app's would stop jellyfin-web from working; the other security headers stay. `POLYFIN_WEB_DIR` can name another copy of jellyfin-web; outside the image, without one, there is no web client and `/` leads to the admin app. jellyfin-web is free software by the Jellyfin contributors and a separate program from Polyfin, which stays under the MIT License: the image contains jellyfin-web 12.1, unmodified, under the GNU General Public License, version 2, copied from the official `jellyfin/jellyfin:12.1` image into `/usr/share/polyfin/jellyfin-web`, with its license and a notice in `/usr/share/doc/jellyfin-web` (from [`third_party/jellyfin-web`](third_party/jellyfin-web)). Its complete source code is attached to every Polyfin release on GitHub, as `jellyfin-web-12.1-source.tar.gz`, and is also at <https://github.com/jellyfin/jellyfin-web/tree/v12.1>. The Dockerfile pins both, side by side, to be changed together when the client is updated.

**Custom CSS and JavaScript:** **Settings › Web player** in the admin app holds three texts for the web client, all empty by default, which changes nothing; **Open the web player** shows the result. **Custom CSS** (up to 256 KB) is Jellyfin's branding CSS: Polyfin serves it at `/Branding/Css` and `/Branding/Css.css` (`text/css`, empty when unset) and in `CustomCss` of `/Branding/Configuration`, and jellyfin-web applies it to every page, unless a user ticks **Disable server-provided custom CSS code** in their display settings. **Sign-in message** (up to 8 KB) is Jellyfin's `LoginDisclaimer`, shown under jellyfin-web's sign-in form: plain text, Markdown or HTML, which jellyfin-web sanitizes. jellyfin-web keeps both for up to a minute before asking again. Administrators can also set them through Jellyfin's `POST /System/Configuration/branding`, which replaces the branding whole as in Jellyfin (a text left out is cleared), and anyone signed in reads them at `GET /System/Configuration/branding`. Deliberate differences: Polyfin has no splash screen, so `SplashscreenEnabled` stays false whatever is posted, and an empty text is left out of the answer, where Jellyfin sends an empty text set as `""`. **Custom JavaScript** (up to 256 KB) has no Jellyfin equivalent: when it is set, Polyfin adds `<script src="custom.js?v=<hash>" defer></script>` to jellyfin-web's `index.html`, after its own script, so it runs on every page of the web client after jellyfin-web's scripts. `/web/custom.js` is served as `application/javascript`, cached for a year at the address with the hash of its content, which changes with it, and revalidated at any other; with no script, there is no tag and no `/web/custom.js`. It is never added to the admin app. The script runs in the browser of every user who opens the web client, with their account, and the display setting does not turn it off: paste only code you trust.

## Configuration

| Variable | Default | Description |
| --- | --- | --- |
| `POLYFIN_DATABASE_URL` | (required) | PostgreSQL URL, e.g. `postgresql://polyfin:password@postgres:5432/polyfin` |
| `POLYFIN_LISTEN` | `:8096` | HTTP address. 8096 is the port Jellyfin clients try by default. |
| `POLYFIN_LOG_LEVEL` | `info` | `debug`, `info`, `warn` or `error`. From `info`, Polyfin logs each Jellyfin endpoint an app calls that it does not serve, with the app's name and version, at most once an hour per endpoint, without the identifiers, query or token of the request. **Settings › Diagnostics › Detailed log** switches to `debug` at once, without a restart, and back to this level when turned off. |
| `POLYFIN_FFPROBE` | `ffprobe` | ffprobe executable (FFmpeg 9.0 or later), a path or a name looked up in `PATH`. The Docker image includes one. |
| `POLYFIN_FFMPEG` | `ffmpeg` | FFmpeg executable (9.0 or later), a path or a name looked up in `PATH`. The Docker image includes one. |
| `POLYFIN_CACHE_DIR` | system temporary directory, `/cache` in the Docker image | Where parts of the files being read, and the HLS segments being played, are kept. Emptied when Polyfin starts. |
| `POLYFIN_CACHE_SIZE` | `10GB` | Disk space the parts of files being read may use, e.g. `10GB` or `512MiB`; at least 256 MiB. Parts read in the last 30 seconds are kept even above it. HLS segments come on top: about a minute ahead of each player by default (**Segments prepared ahead**), up to 1 GB for a 4K remux. |
| `POLYFIN_HWACCEL` | `auto` | GPU video is converted on by default: `auto` for the first that works, `nvenc` (NVIDIA), `vaapi` (AMD, Intel), or `none` for the processor. **Settings › Conversion** can choose another. |
| `POLYFIN_VAAPI_DEVICE` | each render node in turn | Render node VAAPI opens, e.g. `/dev/dri/renderD128`, when several GPUs could. |
| `POLYFIN_SEGMENTS` | `theintrodb,introdb,publicmetadb` | Databases the skip intro, recap, credits and preview buttons come from, the preferred first: `theintrodb`, `introdb`, `publicmetadb`, or `none` for no buttons. They are asked only while **Skip intro and credits buttons** is on under **Settings › Content**; turned off, there are no buttons whatever this says. An order saved under **Settings › Content** replaces the order given here, not the choice of databases. PublicMetaDB is asked only while its API key is saved under **Settings › Content**. |
| `POLYFIN_FONTS_DIR` | `/usr/share/fonts`, with DejaVu in the Docker image | Fallback fonts apps load to render subtitles whose own fonts are missing: the `.ttf`, `.otf`, `.woff` and `.woff2` files of this folder and the folders within. Mount more fonts here for other scripts. A missing folder offers none. |
| `POLYFIN_RECORDINGS_DIR` | (unset) | Folder Live TV recordings are written to, an absolute path. Unset leaves recording off. Polyfin must be able to write to it, or it does not start. |
| `POLYFIN_WEB_DIR` | `/usr/share/polyfin/jellyfin-web`, where the Docker image puts jellyfin-web | Folder of jellyfin-web, the web client served at `/web/`. A folder without its `index.html` leaves the web client off, as without the Docker image. |

The Compose files read their own settings (passwords, ports, image version) from `.env`; see [`.env.example`](.env.example).

## Development

Requirements: Go 1.27, Node.js 24, a PostgreSQL 18 server, and FFmpeg 9.0 or later (`ffmpeg` and `ffprobe`) to play titles. With `POSTGRES_PASSWORD` set in `.env`, `docker compose up -d postgres` starts one on `127.0.0.1:5432`.

```sh
export POLYFIN_DATABASE_URL=postgresql://polyfin:password@127.0.0.1:5432/polyfin
make dev                      # builds the admin app, then runs the server on :8096
npm --prefix web run dev      # optional: admin app with hot reload, proxied to :8096
make check                    # formatting, vet and tests
```

Database tests run when `POLYFIN_TEST_DATABASE_URL` points to a disposable PostgreSQL database, and remux tests when `POLYFIN_TEST_FFMPEG` names an `ffmpeg` executable with `ffprobe` beside it; CI always provides both. Each database test works in its own schema.

Jellyfin API responses are checked against the JSON structure of a real Jellyfin 12.1 server, recorded in `internal/jellyfin/testdata/`. `scripts/jellyfin-fixtures.sh` records them again from a disposable Jellyfin container (requires Docker, curl and jq).
